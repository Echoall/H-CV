# P5 上车集成与比赛就绪

**阶段目标**：系统装到真车上之后依然可靠，队员能独立操作；同时，为设计报告准备好全部素材。

**本阶段需要的实物**：

- 整车：控制组和结构组完成的小车与摆杆机构
- 赛道：按题目尺寸用白布喷绘，或者用胶带贴出
- USB 电流表（或可调电源），用来测功耗
- 备用 TF 卡

**质疑要求**：

- 把系统当成"赛场上会被搬运、被碰撞、遇到干扰"的东西来测试。
- 每找到一种失效方式，都要写进 SOP，给出现场怎么发现、怎么处理。

---

## P5-T01 自启动、安全启动、看门狗、容错

**要求**：

1. 按 04 §9.2 修改 `/sdcard/main.py`：
   - 修改前先备份原文件；
   - 必须实现安全启动开关：创建 `SKIP_AUTOSTART` 文件，或者上电时按住按键，就不自动运行主程序；
   - 上电后留 1.5s 窗口，可以用 Ctrl-C 中断。
2. 实现看门狗：软件看门狗必须有；如果 P0-EXP00 确认有 `machine.WDT`，就同时启用硬件看门狗。
3. 主程序崩溃后要自动恢复，每次恢复都写入日志。
4. 制作一张"比赛用 TF 卡"：在新卡上恢复出固件、程序、配置和标定，整个过程写成脚本（`tools/board/make_sdcard.md`，或者等价的步骤说明）。

**验收标准**：

- [ ] 安全启动开关的 3 种方式（文件、按键、Ctrl-C）都测试过，附证据。
- [ ] 在主循环中人为注入一次异常，程序能自动恢复，恢复时间有记录。
- [ ] 按照做卡步骤，从一张空白 TF 卡做出比赛卡，并成功启动（附日志）。

## P5-EXP16 功耗 🖐

**方法**：

- 用 USB 电流表测量 5V 供电时的电流，分别在以下状态下测：空闲、只做测量、测量加推流、WiFi 连接时的峰值。
- 如果补光灯和 K230 共用电源，就把补光灯单独测出来。
- 如果使用 8–24V 输入口，要在实际电池电压下再测一次。

**验收标准**：

- [ ] 给出电源组需要的数据：平均功耗、峰值功耗、推荐的电源规格（对应 07-C3）。

## P5-EXP17 上车振动与实车运行 🖐

按 06 T11 执行，**需要全队配合**。

**额外要求**：

1. 先在车上完成一次标定和快速复核。
2. 实车跑题目要求 4、5、6 的流程，**每项至少 3 次**，同时录像和记录遥测。
3. 统计每次测试的位置误差，作为控制效果的参考，同时也作为对测量本身的检验。
4. 找出至少一个"和台架测试不一样"的现象，并解释原因。如果确实没有，要写出你检查了哪些方面。

**验收标准**：

- [ ] M12 通过：行驶中测量的标准差 ≤ 1.0mm，偏差 ≤ 2.0mm。
- [ ] 每项实车测试都有完整的录像和 CSV，可以回放。

## P5-T02 比赛工具与操作手册（SOP）🖐

**要求**：

1. 赛前检查脚本 `tools/precheck.py`：一键检查 K230 的状态（READY、帧率、标定 ID、推流），自动引导完成快速复核，最后给出一个总的「可以比赛 / 不能比赛」判定。
2. 写操作手册 `docs/SOP-比赛当天.md`，**写给队员看，不能有代码**。内容包括：
   - 物品清单（含备用 TF 卡、备用 K230、磁铁、测角仪、充电器等）
   - 开机顺序
   - 赛前复核
   - 每项测试前后要做的事
   - 出错时的决策树（例如"复核不通过怎么办"、"图传卡了怎么办"）
   - 赛后封存时要注意的事项
3. 🖐 队员按照 SOP 完整走一遍（模拟比赛），记录时间和遇到的问题，然后修订 SOP。

**验收标准**：

- [ ] 队员完成一次模拟比赛，SOP 根据实际问题修订过（附问题清单和修订记录）。
