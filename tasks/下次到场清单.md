# 下次到场清单

等你方便时再约一次。你负责摆相机、放球、调灯和按窗口提示操作；Codex 负责启动命令、保存录像、数帧和写报告。**第一项拍电脑，第二项才固定相机拍球槽。** 这样只搬一次相机。没有车、控制组或串口工具，也可以先完成前两项。

## 出发前一次备齐

| 做哪项 | 带什么 |
|---|---|
| 图传 | K230、摄像头、电脑、能传数据的 USB 线。第一轮用板子自己的 Wi-Fi。备用随身 Wi-Fi 只在第二轮用，提前准备名称、密码，开启 2.4 GHz，关闭「客户端隔离 / AP 隔离」。密码只在本机向导里输。 |
| 标定和找球 | 标准钢球、球槽或实验摆杆、打印的 V1 尺、胶带、台灯、能固定在槽面上方 28–30 cm 的支架，以及能读出倾角的水平仪。带 V1 尺即可，不要求另买直尺。 |
| 串口 | 万用表、一根母对母杜邦线。没有就留待补测，照常做图传和找球。 |
| 上车 | 控制组同伴、MCU 板、匹配的接线、可停稳的车和供电。提前确认 MCU 的串口、电平和收帧日志怎么导出。没有对接人或车，这部分等资源齐了再约。 |

**时间怎么留。** 以下是排期估算。先留 5–10 分钟做图传首轮，只有需要换网络才多留 5–10 分钟；另留约 45–60 分钟完成标定、静态点和放球/拿球。串口有工具再留约 10–15 分钟，控制组联调另留约 20–30 分钟。只有半小时时，先做图传、固定支架、完成能做的标定项，记下停在哪一步。全部实物验收需要更长时间。

## 1．先拍电脑，看图传能否持续（M3）

1. 保持 K230 接着电脑，关闭 CanMV，双击桌面 **「湖北RTSP复现」**。第一轮先连日常 Wi-Fi，向导会切到板载 Wi-Fi，结束后切回来。
2. 窗口让拔电时，从板端拔掉 USB 和其他供电，灯全灭后，**保持 USB 拔着按回车**。向导会等 Windows 最多 8 秒；如果提示「电脑还能看到板子」，检查板子这一端的 USB 线是否已拔掉，再按回车。最多确认三次。等窗口写出「现在插回 USB」再插回。三次仍能看到板子会记为「未验证」，把记录留给 Codex 即可。
3. 等窗口提示输入「拍」，把相机对准电脑屏幕左半边，支稳以后再输入 **拍**。五声低音后，高音启动采集。保持取景直到窗口提示结束。Codex 会检查右侧回传中的时钟是否在走、录像能否回放、延迟和帧号缺口。

| 向导结果 | 你接下来做什么 |
|---|---|
| 板载 Wi-Fi 通过 | 图传首轮结束，直接去第 2 项。待「图传同时找球」向导通过复核后，另一次上电录 60 秒由 Codex 对照找球速度；如果到场时它已就绪，可在移动相机前先排好这项。 |
| 第一轮有效失败 | 按向导提示把电脑和板子接到同一台随身 Wi-Fi，完成第二次上电，再拍一次。若通过，后续采用随身 Wi-Fi。 |
| 两种网络均有效失败 | 保存两轮结果，停止重复拍摄。由负责人决定下一步试官方 v1.8 或由树莓派单独图传。你可以继续做第 2 项。 |
| 显示「未验证」 | 把提示和记录留给 Codex。上电检查未过、没拍到有效测试等都不能算图传失败。 |

纯图传入口在 `station/bench/湖北RTSP复现.bat`。`station/bench/湖北图传同时找球.bat` 等待复核，且只有纯图传实板 AP 通过后才会开始。届时保持同一取景，按向导提示重新上电，支稳后输入「拍」，五低一高开始，同时记录画面和找球速度。突发发送测试可选，不占用本次必测时间。

## 2．一次摆好槽和尺，把标定、灯光、进出球一起做（M2 + M1）

1. **固定，约 10 分钟。** 镜头垂直朝下，固定在槽面上方 28–30 cm。把 V1 尺贴在槽沿，0 对准杆中心，正数朝控制机构一端。让槽内钢球和 −12 至 +12 cm 的刻度都能入画，台灯正常照明。尺沿调到水平，用水平仪读出实际角度，须在 ±0.2° 内。把这个数告诉 Codex。接下来直到这组拍完，相机、槽和尺保持原位；移动过就先重新标定。
2. **标定并验零，约 5–10 分钟。** 清空槽，等提示再开始。框选**槽沿上贴着的白色尺条**，核对 0 和正负刻度，随后把球心放到印刷的 0 线。你只需看编号、摆球、把手移开并确认；Codex 检查图像和零点，再保存标定。
3. **七个静态点，约 10–15 分钟。** 正常照明下，按提示把球心放在 0、−5、+5、−10、+10、−12、+12 cm。0 点用上一步同一组记录。每点放稳、移开手再按回车，每点至少收 100 个有效帧。Codex 按尺子真值核算，各点平均误差不超过 2 mm，并记录抖动。
4. **灯光和空槽，约 5–10 分钟。** 正常灯下留一次空槽；再分别关闭台灯、从侧面打光，每种光照都拍空槽、再拍 0 线上的球。只动灯和球。空槽目标是零误检，有球时仍检查 2 mm 精度。
5. **进球与拿球，约 5–10 分钟。** 恢复正常照明，先清空。按回车后等五声低音，听到高音，把球从侧面滚入检测区并停在中间。下一段先保持有球，再听高音拿走。手尽量避开检测区。**同一对录像同时交 M1 和 M2**。Codex 回放找球实际进入和离开的首帧，与串口 BALL 上的 `VALID` 对齐：进球后 ≤3 帧变为 1，拿走后 ≤9 帧变为 0。蜂鸣只作动作提示，判读以视频为准。

当前可用入口是 `tools/calib/m2_field.py`。Codex 在仓库根目录用 PowerShell 运行下面命令；角度填写现场读数。每次新建结果目录，保留 `calib.json`、`results.csv` 和各段原始记录。计划中的双击入口复核后可替代此命令。

```powershell
$angle = Read-Host '输入实际测到的尺沿角度（度）'
$out = "station/bench/runs/$(Get-Date -Format yyyyMMdd-HHmmss)-m2"
python tools/calib/m2_field.py $out --level-deg $angle
```

## 3．有表、有线再做串口回环（M1）

先断开外部 MCU。Codex 启动测电平脚本，等看到 `HCV_UART_TX_READY`，用万用表直流电压档，黑笔接 **40 针排针物理 20 脚 GND**，红笔接 **8 脚 TX**。读数 3.0–3.5 V 才继续。待脚本退出，断电，用母对母线把 **8 脚和 10 脚**连起来，再上电。Codex 发 10,000 帧，核对全部收回、CRC 错误为 0、序号连续。做完断电、取走短接线。针号按板卡排针图确认。[接线图与详细说明](../reports/P0-T03-现场操作清单.md)

Codex 的入口如下。`auto` 会查找板子串口。两个命令之间要等用户完成上面的测量和断电接线。

```powershell
$port = "auto"
$uartOut = "station/bench/runs/$(Get-Date -Format yyyyMMdd-HHmmss)-uart"
python tools/board/uart_bench.py voltage --port $port --log "$uartOut/voltage.log"
python tools/board/board.py --port $port run tools/board/m1_uart_loopback.py --timeout 55 --log "$uartOut/uart-loopback.log"
```

## 4．控制组和车到场后，做端到端联调（M4）

1. 带上第 2 项的标定结果，确认短接线已拆。双方断电，由控制组确认 MCU 是 **3.3 V UART**。对照排针接 K230 物理 8 脚 TX → MCU RX，10 脚 RX ← MCU TX，6 或 9 脚 GND → MCU GND，电源脚不互接。双方约定波特率（建议 115200、8N1），记录所用端口和测试号。[对接参数表](../docs/07-对接参数清单.md)
2. 保持车停稳，先让控制组打开 MCU 接收日志，Codex 再运行 `python tools/board/board.py --port auto run k230/main_hcv.py --timeout 30`。清空槽，再放球、移动球。双方核对 BALL 的有效位、位置单位和方向，STATUS 可读、序号连续、CRC 错误为 0。留下 MCU 端日志；只有 K230 发送记录还不能签收联调。
3. 自启动、逃生和看门狗另有上板前置条件。手动原型入口 `k230/boot_manual.py`；根启动文件、硬件看门狗测试须经负责人批准并备好恢复方式。满足这些条件后，再按[开跑 SOP](../reports/M4-开跑SOP草稿.md)实车计时：从上电到可以开跑 ≤2 分钟。这个两分钟是最后一项验收目标，首次接线和联调要单独留时间。

**离场前**把本轮向导结果目录和 MCU 日志留在电脑上，告诉 Codex 哪项因为缺器材或人员跳过。回放、读时钟、算误差、写报告和给 Claude 汇报都由 Codex 完成。
