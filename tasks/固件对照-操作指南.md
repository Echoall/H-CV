# K230 固件对照操作指南

这次用同一块板、同一台电脑、同一根线，检查升级到 Hiwonder v1.8 后活动画面能否稳定播满一分钟。现场唯一的 TF 卡已经升级并确认能启动。**现在直接从「开始图传测试」第 1 步做，选 1。** 旧版恢复方法见[单卡固件切换记录](../reports/M3-单卡固件切换记录.md)。

## 要准备什么

已插好 v1.8 卡的板子、USB 数据线和电脑。电脑先连日常 Wi-Fi。只有第一轮录像确实失败，才用到第二个 2.4 GHz 随身 Wi-Fi；届时电脑和板子需要能在同一网络互通。两轮尽量保持电脑 USB 口、线和供电方式相同。无需摆钢球和纸尺。

## 另有备用卡时才执行的写卡步骤

1. 断开 K230 的 USB 和其他电源，等指示灯全灭再取出原卡。贴上「原卡 v1.4」并放到一边。**整个写卡过程，原卡都不能插在电脑或读卡器上。** 把另一张卡标为「备用 v1.8」。
2. 打开 [官方 v1.8 下载页](https://github.com/kendryte/canmv_k230/releases/tag/v1.8)，在 Assets 里找 `CanMV_K230_Hiwonder_micropython_v1.8-0-gc2d1f5c_nncase_v2.11.0.img.gz` 及其 MD5 清单。核对文件名有 `Hiwonder`。用 7-Zip 把 `.gz` 解压成 `.img`。
3. 官方清单有两行。Windows PowerShell 可在下载目录运行下面两条只读命令，对照**同一后缀**的值。大小写均可。任何一项不同就重新下载，核对成功再继续。

```powershell
Get-FileHash -Algorithm MD5 -LiteralPath .\CanMV_K230_Hiwonder_micropython_v1.8-0-gc2d1f5c_nncase_v2.11.0.img.gz
Get-FileHash -Algorithm MD5 -LiteralPath .\CanMV_K230_Hiwonder_micropython_v1.8-0-gc2d1f5c_nncase_v2.11.0.img
```

| 文件 | 官方 MD5 |
|---|---|
| 压缩包 `.img.gz` | `69faa3dc088322c69419dc7cbfd42dd8` |
| 解压的 `.img` | `65be6d4c5912d611ecb5392dc4c98f96` |

4. 在 Windows 上用读卡器时，打开 [Rufus](https://rufus.ie/) 图形窗口。先看设备列表，再插入**备用卡**，核对新增目标的容量和读卡器。拔掉其他移动磁盘更容易认。点击「选择」打开刚校验的 `.img`。**点「开始」会清掉所选磁盘，认不清目标就停。** 由你手动确认清空提示并等到「准备就绪」，安全弹出。Windows 若提示格式化新分区，点取消。官方亦提供 K230BurningTool 的 USB 烧录流程；这里选用官方文档中与 Windows 读卡器对应的 Rufus 步骤。[读卡器图文说明](https://github.com/kendryte/k230_canmv_docs/blob/ad0b092376e8ae9802e814fb8139599e7ae4fce1/zh/userguide/how_to_burn_firmware.md) · [官方 USB 工具说明](https://github.com/kendryte/k230_canmv_docs/blob/main/zh/userguide/how_to_burn_firmware.md)

## 开始图传测试

1. 将装好 v1.8 卡的 K230 用 USB 接上电脑。关闭 CanMV IDE。在项目 `station/bench` 里双击 `固件对照.bat`。同一张卡升级选 **1**，另外准备了 v1.8 备用卡的选 **3**。每轮都有断电确认。按窗口顺序拔、等、插，避免同次上电重复占用相机。程序先用 `info` 检查 `os.uname()` 的 `machine=k230_canmv_hiwonder` 和 v1.8 版本、构建字段，再查媒体接口。读不出、板型不对或版本不对都会停止。每次上传的同一串口连接也重新检查板型和版本。如果看到「未识别到唯一的 K230」或「USB 连接未恢复」，把窗口里的 VID/PID 列表发过来。
2. 选电脑 USB-A / USB-C / 有供电或无供电的 hub，写下位置和线长（可估计或填未知）。向导把上游相机模块和两个保护模块传进 v1.8 卡的 `/sdcard/hcv/fw18/`，自动建目录并校验文件。相机对准电脑屏幕左半边，你准备好后自己输入 **拍**。电脑响五声低音，最后一声高音发出启动指令。时钟出现后让镜头继续对着跳动的数字，等屏幕提示本轮结束。
3. 第一轮用板子自己的 AP。向导在电脑本地运行，切网期间继续录像，结束后确认电脑连回日常网络。达到门槛就结束。只有真实播放开始且有有效失败证据，并已确认恢复日常网络，才会提示第二轮断电、用 STA 连随身 Wi-Fi。取消、错卡、原网络没恢复或证据不足时，按窗口提示保留记录。若提示手动恢复网络，在 Windows Wi-Fi 菜单点回原网络。
4. **单卡保持 v1.8，做完就结束。** 只有第 1 步选了双卡方案的操作者要完全断电、取出备用卡、装回原卡再上电。按窗口输入「原卡」，或重新打开向导选 **2** 做只读检查。看到「已确认 Hiwonder v1.4 原卡」才算确认旧版启动。
5. 两轮数据在 `station/bench/runs/日期时间-firmware-v18` 下，分 `ap`、`sta`。保留 `summary.json`、录像、时钟截图和串口记录，由项目成员脱敏后分析。电脑从会话启动起每 0.5 秒枚举一次 USB，记录首次消失时刻，并查本轮 Windows PnP 1010 事件。如果手头碰巧有图传期间的 5V 实测读数，可在结束后填入；没有就直接回车。

## 判读单

每轮填：网络模式、供电口/hub、线长、可选 5V 读数、首次 USB 消失和 1010 事件时间、固件、启动至 EOF、变化画面连续秒数、录像秒数、分辨率、参考帧/缺失数/缺口%、截图数、板端最后心跳和结束标记、原网络恢复情况。原卡确认另存 `日期时间-original-info/summary.json`。

| 指标 | 现场通过条件 |
|---|---|
| 电脑看到的活动画面 | 连续变化 ≥60 秒，使用渲染帧变化记录；静止的最后一帧不计 |
| 保存的录像 | H.264、640×360、视频轨 ≥58 秒，TCP 播放；无提前 EOF |
| 录像连续性与截图 | H.264 参考帧号缺口 ≤1%，保留时钟截图供人工读数 |
| 板端结束 | 主机读取结束标记并以 0 退出。湖北原版 `stop()` 对若干底层停止异常会跳过，标记代表停止函数已返回且工作线程已退出 |

- v1.8 通过：对比同网络 v1.4 的失败结果，支持固件因素。单卡模式下物理 TF 卡相同，双卡模式下卡和镜像均改变。一次通过尚不足以定位到某个补丁。M1/M2 的迁移验收等对照结束后另行决定。
- v1.8 的 AP、STA 均有效失败：升级未解决本板问题。下一步在相同设置下做供电对照，再评估板子；目前没有板子损坏的诊断依据。
- 有一轮未验证：写明卡在版本、网络、播放、截图或恢复哪一步，保留已取得的数据。

## 为什么换固件

原卡为 v1.4-19-ga7de1c8，构建于 2025-11-06。11 月 26 日湖北版在 v1.4 上的活动画面 AP 10.533 秒、STA 8.893 秒。两者均 EOF；仅 AP 那轮有紧邻 EOF 的 Windows USB 移除事件。[本机取证表](../reports/M3-断流离线取证.md)

| 核对的发布记录或源码 | 与本试验的关系 |
|---|---|
| [v1.4](https://github.com/kendryte/canmv_k230/releases/tag/v1.4)、[v1.5-legacy](https://github.com/kendryte/canmv_k230/releases/tag/v1.5-legacy) | 旧版基线；legacy 汇总了 VICAP 多通道缩放/裁剪、VENC 多通道示例和 AI+RTSP 示例。|
| [v1.6](https://github.com/kendryte/canmv_k230/releases/tag/v1.6)、[WLAN 修复 ea6def96](https://github.com/canmv-k230/rtsmart/commit/ea6def96) | 改用 MPP 私有缓冲池，修复 WBC+RTSP；WLAN 管理代码更正互斥锁释放，可解释某些失去响应，尚无本板调用栈。|
| [v1.7](https://github.com/kendryte/canmv_k230/releases/tag/v1.7)、[MPP b53767c5](https://github.com/canmv-k230/mpp/commit/b53767c5) | RTSP 读线程去掉固定 10 ms 睡眠；原始队列增加上限和计数；已分包队列溢出时按 access unit 丢弃。发送时间戳参与计算。这些变化可能减少突发积压、残帧和色块；湖北原脚本仍传常数 1000，对照保持原写法。|
| [RT-Smart ce7ff552](https://github.com/canmv-k230/rtsmart/commit/ce7ff552) | Hiwonder 的 lwIP 配置中 PBUF 44→160，TCP_SEG 176→256，INPKT 16→64，NETCONN 和 TCP 线程邮箱 8→32，**以太网线程邮箱 8→64**。大关键帧突发时可用空间更多。上述两个补丁均已进入 v1.7 标签。|
| [v1.8](https://github.com/kendryte/canmv_k230/releases/tag/v1.8) | 整理 VICAP 流管理，修 CSC 绑定通道；USB DWC2 调整端点 FIFO、停滞清理和错误日志。USB 移除和视频 EOF 在旧记录中既可相邻也可分开，现场分别观察。|

**湖北脚本 API 核对。** 原版取自 [固定上游提交](https://github.com/VincentttWang/NUEDC_2026/blob/ed079e501579cbe891e8339b6998f3ea53a12428/2026H/firmware_G3507/k230/rtsp_camera_stream.py)，连同 MIT 许可保存在 `tools/board/hubei_v18/`。向导导入原版 `CameraRtspServer`，保留采集、线程、编码、物理地址发送和释放顺序。另写入口负责网络、倒计时、最长会话及记录。v1.4 使用的适配脚本单独保留。

- v1.8 的 `Sensor(**kwargs)`、`reset()`、`set_framesize(width=…, height=…, alignment=12)`、`set_pixformat(YUV420SP)` 和 `run()` 与原版调用相符。[sensor.py](https://github.com/kendryte/canmv_k230/blob/v1.8/port/builtin_py/media/sensor.py)
- `Encoder.SetOutBufs` 构建私有池，`Create` 关联私有池，后续 `Start/GetStream/ReleaseStream/Stop/Destroy` 都有对应接口。`MediaManager.link` 保留；v1.8 的显式 `init()/deinit()` 只打印弃用提示，故按湖北原版的生命周期运行。[vencoder.py](https://github.com/kendryte/canmv_k230/blob/v1.8/port/builtin_py/media/vencoder.py) · [media.py](https://github.com/kendryte/canmv_k230/blob/v1.8/port/builtin_py/media/media.py)
- 原生 `rtsp_server` 提供初始化、建会话、启动和停止，以及按会话名、物理地址、大小、时间戳发送的四参数方法 `rtspserver_sendvideodata_byphyaddr`。源码一致性和电脑模拟已核对，实板可用性待现场验证。[RtspServer.c](https://github.com/kendryte/canmv_k230/blob/v1.8/port/multi_media/RtspServer.c)
