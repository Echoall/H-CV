# MVP 路线：先做出可用成品 v1（2026-11-21 起生效）

> 负责人已批准。本文件优先级**高于** P2–P5 任务书中的原有排序。原任务书仍是技术细节的依据；本文件决定"先做什么、做到什么程度"。

## 原则

1. 先把整条链路打通、装上车能用，再做精。
2. "能用"由硬指标定义。每项都要有原始数据，并经 Manager 复算；达不到就不算完成。
3. 锦上添花的优化放到上车之后，用实车数据证明有必要再动手。
4. 测试诚信规则（AGENTS §10）照旧。

## 里程碑

### M1 板上跑通（Codex 独立完成；只需用户接一根杜邦线）

内容：`k230/main_hcv.py`（P3-T02 的 MVP 部分），在板上实时运行：
`snapshot(CHN0) → ProfileDetector → 像素到毫米（暂用名义比例，接口按 LUT 设计）→ KalmanTracker → BALL 帧经 UART1 发出`；每 0.5 s 发一次 STATUS；处理 RUN_INFO/CMD 的接收（非阻塞）。主循环零分配，GC 定时执行。

验收：
- [ ] 连续运行 ≥ 10 分钟，720p@90，用**总时长法**统计丢帧数（`(t1−t0)/帧周期 − 处理帧数`，GC 时间包含在内）= 0，或者给出丢帧数和原因。
- [ ] 各阶段耗时 p50/p95/p99/max；单帧处理 p95 ≤ 6 ms。
- [ ] 画面中没有球时 BALL 帧的 VALID=0；放入球后 ≤ 3 帧内 VALID=1。
- [ ] UART1 回环（物理脚 8↔10，等用户接线）：板上编码 → 回环 → 解码，10,000 帧 CRC 错误 = 0，序号连续。
- [ ] 极性配置为 both 时，STATUS 的 err=10。
- [ ] 带 guard 的退出路径实测有效。

### M2 测得准（需要用户到场约 1 小时）

准备（Codex 先在合成数据上完成）：`ruler.py` 黑白刻度尺的长刻度检测；标定工具：摆杆水平时检测长刻度，生成像素→毫米 LUT 并写入配置（绑定相机配置指纹）。每帧倾斜补偿做成开关，**默认关闭**。

现场验收：
- [ ] 球静止在 0、±5、±10、±12 cm，各测 ≥ 100 帧：|均值误差| ≤ 2 mm，标准差另行报告（以刻度尺读数为真值）。
- [ ] 开灯/关灯/侧光：空槽误检 = 0；有球时误差仍 ≤ 2 mm。
- [ ] 拿走球后 ≤ 9 帧（0.1 s）内 VALID=0。
- [ ] 采集一小批真实数据集（EXP-04 的精简版），用于以后的回归测试。

### M3 看得见（需要用户带笔记本到场约 20 分钟）

内容：K230 开 AP，CHN1 硬件编码后以 RTSP 推流；笔记本用 VLC 或 ffmpeg 显示，配一个脚本一键开始/停止录像，每次测试一个文件，可以回放。参考：VincentttWang 的实测是 VLC `network-caching=200` 时延迟约 200 ms。

验收：
- [ ] 画面稳定实时，延迟实测 ≤ 300 ms（拍屏法或时间码法）。
- [ ] 录像完整，可以回放。
- [ ] **开着图传时** M1 的丢帧数和耗时不变差（对比数据）。

### M4 能上车（需要用户和控制组）

- [ ] 上电自启动，**必须带逃生机制**。方案先提交 Manager 批准再实施，例如启动时检测某个按键或 TF 卡上的标志文件，存在就不进主循环。
- [ ] 和控制组的 MCU 实际联调：对方收到帧，序号连续，CRC 错误 = 0。
- [ ] 一页 SOP：从开机到可以开跑 ≤ 2 分钟。

## 暂停（上车后再定）

交替色块刻度尺；两点几何的精细化、θ 平滑、在线 scale 估计；BlobDetector 和 EXP-06 对比；CR-P1-01 提速；上位机曲线、叠加标注和 UDP 遥测；60 分钟长跑、功耗、启动时间的完整版；markers.py（黑块方案已取消，保持现状）。

## 上车后的优化清单

倾斜补偿的实车效果（EXP-08）；光照鲁棒性；振动；延迟优化（目标 < 25 ms）；图传叠加标注；长时间稳定性；提速。

- 评估增量内存回收或缩短每 30 秒一次的段间停顿。先细分计时，再用实车 UART 到达间隔验证控制端所受影响。基线见 [v1.8 独占长跑](../reports/M1-v18独占长跑实测.md)。
