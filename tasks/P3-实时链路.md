# P3 实时链路

**阶段目标**：把检测做成完整的实时系统，满足帧率（M4）、延迟（M5）、检出（M6）、动态跟踪（M7）指标，并交付给控制组联调。

**本阶段需要的实物**：

- P2 的全部实物
- 1 个 LED 和 1 个 330Ω 电阻，外加杜邦线（用于测延迟）
- 1 个 3.3V 电平的 USB-TTL 模块（用于嗅探串口数据和模拟 MCU）
- （联调时）控制组的 MCU 板

**质疑要求**：

- 检查跟踪器有没有"掩盖"检测问题。例如门控把真实的快速运动当作异常拒绝掉，或者外推让丢失看起来像是有效。
- 检查延迟预算里有没有漏算的环节。

## P3-T01 跟踪器

**目标**：按 04 §7 实现一维常速度卡尔曼跟踪器。

**要求**：

1. 实现 `tracker.py`，代码在板上和电脑上通用。
2. 单元测试使用合成轨迹，覆盖以下情况：
   - 匀速运动、匀加速运动
   - 撞到挡片后反弹（速度瞬间反向）
   - 单帧野值、连续 2 帧野值
   - 真实的跳变（球被手拿走后，放到另一个位置）
   - 连续丢失 1、3、5 帧
   - 时间戳回绕
3. 每种情况都要断言以下行为：何时 `VALID`、何时 `PREDICTED`、何时判为丢失；何时重新捕获；以及位置和速度误差的上限。
4. 和 α-β 滤波器做对比（可选）：如果两者效果相当，就选更简单的，并在报告中写明。

**验收标准**：

- [ ] 测试通过。
- [ ] 报告中有一张"真实轨迹、测量值、滤波值"对比图，用来展示反弹和野值场景。

## P3-T02 主程序集成

**目标**：实现 `k230/hcv/main_hcv.py`，包含 02 §1.2 的主循环和 04 §9.1 的状态机。

**要求**：

1. 按 ICD 发送 BALL 帧（每帧一次）和 STATUS 帧（2Hz）；非阻塞地接收 RUN_INFO 和 CMD；收到 PING 时立即回复。
2. 实现 `health.py`：分阶段计时，在 1s 的窗口内统计 p50、p95、p99。
3. 实现日志：使用环形缓冲，按配置写到 TF 卡（默认只写事件，不写每帧数据）。
4. 遥测接口先只留一个桩（P4 再实现）。
5. 程序可以被干净地停止：收到停止信号或运行时间到达上限时，释放全部资源。
6. 通过 `tools/sim/mcu_sim.py` 联调：模拟 MCU 发送 RUN_INFO（测试 5 开始 → 30s → 结束）。K230 必须正确记录事件，BALL 帧的流不能中断。

**验收标准**：

- [ ] 在 PC 模拟 MCU 的情况下连续运行 10 分钟：BALL 帧率 ≥ 60Hz；串口 CRC 错误为 0；PC 端统计的 seq 丢帧率 ≤ 0.1%，同时要说明丢帧发生在哪一端。
- [ ] 人为制造 4 种故障，每种都能正确上报并恢复：
  - 拔掉摄像头排线（**断电后**再拔，然后上电测试）
  - 删除标定文件
  - 修改 config 使指纹不匹配
  - 遮住全部标记 2s

  要求状态和错误码正确，恢复后能自动回到 READY。

## P3-EXP09 端到端延迟（LED 法）🖐

**问题**：从曝光到串口发出，真实的延迟是多少？

**方法**：按 06 T5 执行。

1. 由 Codex 指定一个空闲的 3.3V GPIO 和接线方式（LED 正极串 330Ω 电阻接 GPIO，负极接 GND）。🖐 队员接线，并把 LED 固定在画面内、ROI 之外。
2. 分别在 3 种配置下测量：检测器 A、检测器 B、推流开启（推流在 P4 完成后补测）。每种配置 ≥ 500 次。
3. 同时记录 `age_ms`，并分析"曝光 → snapshot 返回"和"snapshot 返回 → 发出"两部分各占多少。
4. 把测得的 p95 写进 `config.latency_const_ms`，供 STATUS 上报。

**产出**：延迟分布图和分解表。

**验收标准**：

- [ ] 每种配置都有 ≥ 500 个样本。
- [ ] p95 ≤ 35ms（M5）。如果超标，指出最大的贡献环节，并给出优化建议。

## P3-EXP10 动态跟踪 🖐

**问题**：钢球快速运动时，测量是否依然连续、准确？

**方法**：按 06 T6 执行。

1. 🖐 用垫块把摆杆固定在 2°、4°、6°（如果机构允许，再加 10°），让球从上端静止释放，每个角度 5 次。
2. 对拟合残差、丢失次数、反弹时的重新捕获情况做统计。
3. 如果 P0-EXP02 证明曝光可以设置，就再比较 2 种曝光时间对运动模糊和残差的影响。
4. 计算加速度 a 与 (5/7)·g·sinθ 的比值，交给控制组建模用。

**验收标准**：

- [ ] 拟合残差的 RMS ≤ 1.0mm（M7）；正常滚动段没有出现丢失。
- [ ] 反弹后在 3 帧以内重新捕获；如果没做到，要在报告中说明发生的次数。

## P3-EXP11 串口完整性与 MCU 联调 🖐

**方法**：

1. 用 PC（USB-TTL）分别在 115200 和 460800 两种波特率下，连续接收 10⁵ 帧，统计 CRC 错误、丢帧，以及帧间隔分布。
2. 🖐 和控制组的 MCU 实际联调（如果对方已经准备好）：
   - MCU 用 `protocol/c` 库解析数据，回传一个统计报文（或者通过它自己的调试口打印统计）；
   - 双方核对丢帧率；
   - 验证 RUN_INFO 链路；
   - 验证 07-A12 中的失效保护：拔掉 TX 线，MCU 要在 100ms 内进入安全状态。
3. 如果控制组还没准备好，就用 PC 模拟器完成，并在报告中注明。

**验收标准**：

- [ ] 10⁵ 帧的 CRC 错误为 0。
- [ ] 联调结果有记录（实际 MCU 或模拟器，二者必选其一，并注明是哪一种）。

## P3-T03 「CV v1」交付包

**目标**：为控制组整理一份可以直接使用的交付包。

**内容**（写成 `reports/P3-CV-v1-交付说明.md`）：

1. 接线图和串口参数。
2. 实测性能：帧率、延迟（p50/p95）、静态噪声、精度、有效范围、反弹恢复时间、丢失概率。
3. 状态位的使用建议：什么时候信任数据、什么时候要降低信任、什么时候进入安全动作。
4. C 库和模拟器的使用方法。
5. 已知限制：例如极端光照下的表现，以及倾角超过 θmax 之后的表现。

**验收标准**：

- [ ] 交付说明中的每个数字都能追溯到 P2 或 P3 报告里的原始数据。
