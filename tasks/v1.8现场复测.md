# v1.8 现场复测

使用 `station/bench/v1.8现场测试.bat`。准备 v1.8 卡、原 USB 线、可恢复的日常 Wi-Fi，以及能把镜头固定对准电脑左半屏的位置。每次实拍前确认「拍」，五声低音后的一声高音开始采集。每一项结束都会保存记录，下一项开始前可以按提示退出。

| 顺序 | 操作者需要做什么 | 检查内容 |
|---|---|---|
| 1 · S0a | 按提示单独上电。依次确认两次单帧采集，两帧之间保持连线。 | 两次均取到 320×240 灰度图，确认释放、解释器连续性及最后的板端版本。只记录尺寸和状态。 |
| 2 · S1 | 单独上电，固定镜头，留出约十分钟。 | 实际选择的 720p90 模式、采集时长、丢帧、处理 p95。任意取景可测时序。 |
| 3 · 接收器对照 | 架好相机对准电脑左半屏。按提示分别确认 VLC 和 ffplay 两轮，每轮单独上电。 | 两轮都直连同一板载 AP。左侧是电脑时钟，右侧是摄像头回传。每轮保留截图，可稍后填读数。至少 5 组有效读数才计入光学测量。 |
| 4 · S4 | 镜头朝向不限。先 1080p60，再 720p90，两轮单独上电。 | 同一路视频录制和低延迟显示，并行运行 CHN1 找球，用接收端帧到达时刻核实至少 60 秒重叠窗口。 |
| 5 · S2 历史记录 | 无需操作板子。 | 读取已有实拍日志。现场客户端重连后的健康状态保留为未验证。 |

S0b/S0c 所要求的是整套视频服务在同一上电周期及软复位后的重新启动。S0a 的结果仅覆盖 Sensor；目前仍逐项单独上电。可单独运行 `python -m station.bench.sensor_reuse --sensor-soft-reset` 检查解释器软复位后的 Sensor，不能用这个结果给整套视频服务签收。

结果在 `station/bench/runs/*-v18-visit/`。`visit.json` 区分各项结果、光学样本情况和仍缺的实板证据。程序返回 1 表示有步骤失败；返回 2 表示仍有实板项目待验收或操作者提前退出。可选的 M2 标定另用 `M2标定与验收.bat`，需要支架、尺子和钢球。

## 电脑演练

`python -m station.bench.v18_visit --runs <新目录> --simulate <ffmpeg.exe> <mediamtx.exe>`。S0 使用模拟解释器执行板端脚本，S1 复算 v1.4 历史日志，接收器和 S4 使用本机合成视频，S4 同时对存档的图像条带运行找球算法。硬件模式、相机曝光、现场网络和光学延迟均须现场测量。原先的双连接回环仍可用 `python -m station.bench.v18_rehearsal <新目录> <ffmpeg.exe> <mediamtx.exe>` 单独运行。

## 2026-11-28 电脑演练记录

首次演练两次各录约 20 秒，VLC 渲染输出中的图像分别连续变化 19.461 和 19.463 秒。并行回放记录 4,081 帧视频，活动画面 67.412 秒；检测与活动画面重叠 66.000351 秒，共 3,960 个检测帧。历史独占 M1 日志重算为 54,769 帧，最大窗口处理 p95 为 1,827 µs。

后续从现场入口运行时出现波动。第二次并行录像有 4,079 帧，视频轨约 67.98 秒、参考帧号无缺口，但 VLC 日志报告显示迟到并丢弃解码帧，持续变化只有 36.520 秒。缩减编解码线程数、增加无窗口渲染管道缓冲都没有稳定解决，两个试改已撤回。保留了渲染帧计数以便和文件帧数分别核对。每轮的时长、帧数、缺口、告警次数与通过状态均在[复测证据](../reports/data/M3/bench/2026-11-28-visit-rehearsals.json)。

单独模拟发布端定时结束，VLC 的确收到 EOF，录像可解出 1,129 帧。该试验只验证本地接收器能记录结束事件。板端线程退出后能否清理、串口是否继续响应，仍须实体设备证据。当前向导按草案提交复核，尚未取得稳定的电脑端整套复测结果。

另一轮回环每秒用 Windows `GetSystemTimes` 采样。每个相邻样本的整机忙碌率为 `100 × (1 − Δidle / (Δkernel + Δuser))`，表内均值为阶段样本的算术平均。录像取视频轨中的帧数，渲染取播放器输出的帧数，告警取 VLC 日志里 `late frames, dropping frame` 的出现次数。[逐秒样本和阶段汇总](../reports/data/M3/bench/2026-11-28-visit-cpu.json)

| 本机合成视频 | CPU 均值 / 峰值 | 录像帧 / 渲染帧 | 最长持续变化 | 迟到告警次数 |
|---|---:|---:|---:|---:|
| 首次连接 | 6.98% / 16.14% | 1,200 / 937 | 9.630 秒 | 62 |
| 再次连接 | 7.01% / 14.99% | 1,198 / 1,095 | 12.441 秒 | 22 |
| 同时回放检测 | 8.55% / 21.62% | 4,077 / 3,032 | 20.466 秒 | 317 |

三段都未达到连续显示目标。整机 CPU 采样未见饱和，单核峰值、调度等待及播放器内部缓冲均未测量。一个告警可能涉及多个帧，不能据告警次数计算丢帧率。
