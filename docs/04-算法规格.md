# 04 算法规格

版本 v1.0（2026-11-19，Manager）。文中参数都是**初值**，最终取值由实验确定，并写回 `config.json` 和本文。

约定：`u` 是检测通道图像中沿摆杆方向的像素坐标（列号，浮点数，亚像素精度，**已经加上了裁剪偏移**，即以检测通道全图为基准）；`v` 是行号；`D` 是钢球直径对应的像素数（由标定得到，约 20px@640 宽）。

---

## 1. 图像几何与 ROI

- 安装要求：摆杆轴线在画面中尽量水平（偏差 ≤ 2°），+x 方向对应画面右侧（用 `hmirror`/`vflip` 调整），摆杆中心 O 尽量位于画面中央（±10% 画面宽度）。
- **球 ROI**：位于槽内、沿摆杆方向的矩形条带。宽度覆盖 −125 到 +125mm，并左右各留 `D` 的余量；高度约为槽口宽度的 60%（只包含槽中央，避开槽沿、刻度和接缝）。
- **标记 ROI**：位于与刻度相对的那一侧槽沿上，是包含 3 个参考标记的窄条带。
- ROI 的位置在标定时确定并写入 `config.json`，运行时**不会自动搬移**。摄像头被碰动后，由自检发现（§9.2）。
- 如果 sensor 支持按通道硬件裁剪，检测通道只输出包含两条 ROI 的最小条带（EXP-01 确认）。

## 2. 参考标记（3 个）

### 2.1 物理规格（要和结构组确认，见 07）

- 哑光黑色矩形贴片（例如黑色电工胶带剪成的小块）。沿 x 方向宽 5mm，垂直方向高 4mm。
- 贴在**槽外**、与刻度相对的那一侧槽沿表面上。中心分别位于 x = −110、0、+110mm（位置精度 ±0.5mm；实际位置以标定时的记录为准，不要求贴得绝对精确）。
- 如果摆杆是深色管子，就改用白色哑光贴片，同时把 `markers.polarity` 设为 `"bright"`。

### 2.2 检测

每帧对每个标记执行：

1. 搜索窗口：以上一帧位置（首帧用标定参考位置）为中心，u 方向 ±`search_px`（默认 12px），v 方向覆盖标记条带。
2. 计算窗口内的列剖面 `m[u]`（对条带的各行求平均）。
3. 基线 `b` 取窗口两端各 3px 的中位数；凹陷深度 `d[u] = max(0, b − m[u])`（标记为亮色时，正负号反过来）。
4. 有效性检查：峰值深度 ≥ `marker_min_depth`（初值取基线的 25%），并且半高宽在 [0.6, 1.5] × 期望宽度之内。
5. 亚像素位置 `u_i = Σ u·d[u] / Σ d[u]`，只对半高宽范围内的点求和。
6. 输出 `(u_i, ok_i, depth_i)`。

单个标记连续 30 帧无效，记为标记丢失；3 个标记持续 1s 以上全部无效，置错误码 6。

## 3. 检测器 A：阈值 + 斑点

1. 在球 ROI 内计算统计量：中位数 `med` 和 `MAD`。如果 CanMV 的 `get_statistics` / `get_histogram` 不能直接给出，就在稀疏采样的像素上计算。
2. 阈值：
   - 暗模式：`[0, med − k_dark·1.4826·MAD]`
   - 亮模式：`[med + k_bright·1.4826·MAD, 255]`
   - `polarity` 可以是 `dark`、`bright` 或 `both`（`both` 表示两者都找，再合并）。
3. 调用 `find_blobs(thresholds, roi=球ROI, pixels_threshold=0.15·D², area_threshold=0.2·D², merge=True, margin=2)`。
4. 筛选候选斑点：宽和高都在 [0.5D, 1.5D] 之内；斑点中心的 v 偏离槽轴线不超过 0.3D；填充密度 ≥ 0.25。
5. 过载保护：原始斑点超过 `max_blobs`（默认 32）个时，本帧判为无效，置 LOW_CONF，并在统计中计数一次。【调研#3】
6. 从剩下的候选里选得分最高的一个。得分 = 尺寸匹配度 × 密度 − λ·|u − u_pred|/D，其中 `u_pred` 是跟踪器的预测位置；没有预测时 λ = 0。
7. 输出 `u = blob.cxf()`（亚像素质心）。质量取决于对比度与噪声之比，以及尺寸匹配度。

## 4. 检测器 B：列剖面 − 背景基线（一维方法）

1. 列剖面：`p[u] = mean(ROI[:, u])`。用 `ulab` 按 axis=0 求平均，**禁止用 Python 逐像素循环**。
2. 背景基线 `b[u]`：
   - **初始化**：使用标定时拍下的空槽剖面（`calib` 中存放的 `bg_profile`），并按当前的标记补偿结果平移和缩放到当前画面。
   - 没有空槽剖面时，用空间鲁棒基线代替：对 `p` 做宽度为 3D 的滑动最大值（暗球情况）或最小值（亮球情况）后再平滑。具体用哪种，由 EXP-06 决定。
   - **在线更新**：只更新 `|u − u_ball| > 1.5D` 的列，`b = (1−α)·b + α·p`，α 初值 0.05。光照整体变化时，基线会自动跟上。
3. 偏差：`d[u] = |p[u] − b[u]|`。取绝对值，所以不管球是亮是暗都适用。也可以配置成只取暗或只取亮。
4. 平滑：用宽度为 D 的盒式滤波得到 `s[u]`（用 ulab 的累加和实现）。
5. 噪声估计：`σ = 1.4826·MAD(d)`，在整个 ROI 上计算。
6. 选峰：在 `s` 上找最大值；有预测位置时，在预测位置 ±gate 的范围内优先选。`SNR = s_peak / σ`，要求 SNR ≥ `snr_min`（初值 6）。
7. 亚像素定位：在 `[k − D/2, k + D/2]` 范围内，对 `d − floor` 求加权质心，其中 floor 是窗口边缘的值。
8. 质量 `q = clamp(255·(SNR − snr_min)/(snr_good − snr_min), 0, 255)`，`snr_good` 初值 20。

> 调研中的"扫描线对比度"方法【调研：kevin】可以看作只取单行时的特例，EXP-06 中把它作为对照组。

## 5. 标定

### 5.1 前提条件

- 摄像头、支架、补光已经是最终状态；`config.json` 中与指纹相关的项已经确定。
- 摆杆调到水平（用手机测角仪或水平尺，误差 ≤ 0.2°），并在整个标定过程中保持不动。可以由控制组把执行机构锁在水平位置，也可以垫块固定。
- 3 个参考标记都已贴好，并能正常检测到。

### 5.2 流程（电脑端工具 `tools/calib/` 与板上程序配合，逐步提示操作员）

1. **空槽**：取走钢球，采集 60 帧，记录 `bg_profile` 和 `markers_ref`。
2. **逐点**：x 从 −120 到 +120mm，每 10mm 一个点，共 25 个点。
   - 每个点：操作员把**小磁铁贴在管子外壁下方**，把钢球吸在刻度 x 处，使球心对准刻度线，然后确认。
   - 程序采集 30 个有效帧，取 u 的中位数，并计算标准差。
   - 如果标准差大于 0.3px，或者标记相对参考位置偏移超过 1px，就要求重做这个点。
3. **生成标定表**：检查 u 是否严格单调。用留一法交叉验证：依次去掉每个内部锚点，用它两侧的相邻锚点插值预测它，得到交叉验证误差，统计最大值和 RMS。
4. **保存**：写入 `calib.json`，同时拷贝到电脑上；生成标定报告，包含锚点表、交叉验证结果，以及标定拟合曲线和残差图。

### 5.3 插值

- 默认使用**分段线性插值**。
- EXP-07 会比较单调三次插值（PCHIP）；如果它的交叉验证误差小 30% 以上，就改用 PCHIP。
- 外推：超出 ±120mm 的部分，用最后一段的斜率外推，最远到 ±125mm，并置 `EXTRAPOLATED` 位；超出 ±125mm 的结果判为无效。

### 5.4 快速复核（赛前或搬运后执行，≤ 1 分钟）

1. 摆杆调到水平。
2. 用磁铁把球依次放在 0、+50、−50mm，每个点采 20 帧。
3. 通过条件：每个点的 |误差| ≤ 1.5mm，并且标记相对参考位置的偏移 ≤ 3px。
4. 结果写入 `check_<时间>.json`，并在笔记本上显示通过或不通过。
5. **不通过就不能比赛**，必须先查原因（多半是摄像头或支架被碰动了），然后重新标定。【调研#5】

## 6. 倾斜与平移补偿

### 6.1 原理（见 02 §2）

摆杆上一条直线上的点，在图像中的 u 坐标与它在直线上的位置之间是**一维射影关系**。3 个参考标记正好确定当前画面与标定画面之间的一维射影变换：

```
P(u) = (a·u + b) / (c·u + 1)，满足 P(u_i) = u_i0（i = L, C, R）
```

其中 `u_i` 是当前帧中标记的位置，`u_i0` 是标定时记录的标记参考位置。把它写成 3 个线性方程 `a·u_i + b − c·u_i·u_i0 = u_i0`，直接求解即可。

### 6.2 运行时

1. 3 个标记都有效时：求出 P，计算 `u_c = P(u_ball)`，然后 `x = LUT(u_c)`，并置 `COMP_FULL`。
2. 合理性检查：如果 `|c|·W > 0.2`（其中 W 是图宽），或者方程组的条件数过大，说明解不合理，就退回到第 3 步。
3. 只有 2 个标记有效时：用相似变换 `P(u) = s·u + t` 代替，置 `COMP_DEGRADED`。
4. 标记不够，但 RUN_INFO 里有 `rod_angle` 时：用几何模型补偿（需要 `config` 中的安装高度 H 和合页位置；属于可选功能），置 `COMP_DEGRADED`。
5. 以上都不行：不做补偿，置 `COMP_DEGRADED` 和 `LOW_CONF`。

### 6.3 视觉估计倾角（可选，F16）

由射影参数 c 和相似缩放量可以推算摆杆端点的高度变化，从而估计 θ。这一项在 EXP-08 中与实测角度对比，只有误差 ≤ 1° 时才在 `tilt_est` 字段中输出。

## 7. 跟踪滤波（一维常速度卡尔曼）

- 状态 `[x, v]`（单位 mm、mm/s），dt 取 `t_cap` 的差值。
- 预测：`F = [[1, dt], [0, 1]]`。过程噪声按白噪声加速度模型，`Q = q·[[dt³/3, dt²/2], [dt²/2, dt]]`，`q = q_accel`。
- 测量噪声：`R = (r_meas / max(q_norm, 0.2))²`，其中 `q_norm = quality/255`，`r_meas` 初值 0.3mm。
- 门控：新息 `|y| > max(gate_mm, 3·√S)` 时拒绝这次测量，记一次拒绝。
- 重新捕获：连续 `reacquire_frames`（3）个被拒绝的测量彼此相差在 gate 之内时，认为球确实到了新位置，用这些测量重新初始化状态（v 取它们的差分），并在日志中记一次 `REACQUIRE`。
- 外推：没有测量或测量被拒绝时只做预测，最多 `coast_max`（3）帧，这期间置 `PREDICTED`；超过就判为**丢失**，并重置跟踪器。
- 限幅：|v| ≤ 2000mm/s。
- 输出：`pos_filt = x`，`vel = v`。`pos_raw` 为本帧**被接受的**测量值（未滤波）。被门控拒绝的帧置 `VALID=0`，`pos_raw` 置为 INT16_MIN，避免 MCU 误用；原始测量值只写进遥测，供分析使用。
- 边界：跟踪器只做测量层面的滤波，不做为控制服务的超前预测（ADR-11）。

## 8. 质量值 quality

`quality = 检测器质量 × 补偿系数 × 范围系数`。其中补偿系数：COMP_FULL 取 1.0，COMP_DEGRADED 取 0.6，无补偿取 0.3；范围系数：正常为 1.0，EXTRAPOLATED 为 0.7。结果取整到 0–255。`quality < q_low`（初值 80）时置 `LOW_CONF`。

## 9. 启动、自检、容错

### 9.1 状态机

```
BOOT → INIT（读配置、初始化摄像头和串口）
     → CALIB_LOAD（检查指纹）── 不匹配或缺失 ──► NO_CALIB（照常发 BALL，CALIB_OK=0）
     → SELF_CHECK（标记 C 的 u 偏移 ≤ 6px、v 偏移 ≤ 4px；阈值由 EXP 确定）── 失败 ──► DEGRADED（err=5）
     → READY
任何阶段出现异常 → FAULT（记日志，1s 后重新初始化；连续 3 次失败后保持 FAULT，并持续发送 STATUS）
```

无论处在哪个状态，只要串口可用，就**持续发送 STATUS**；只要摄像头可用，就持续发送 BALL。

### 9.2 安全启动开关（P5 启用自启动时必须同时实现）

- `/sdcard/main.py` 只做两件事：先检查安全开关，再 `import` 并运行 `/sdcard/hcv/main_hcv.py`。
- 存在 `/sdcard/hcv/SKIP_AUTOSTART` 文件，或者上电时按住配置指定的按键，就**不启动**主程序，停在 REPL。
- 上电后先等 1.5s（这期间可以从 USB REPL 按 Ctrl-C 中断），再启动主程序。
- 主程序抛出未捕获的异常时，写日志后重新进入初始化，绝不让板子停在一个无响应的状态。

### 9.3 看门狗

- 软件看门狗：主循环的单次迭代超过 500ms，就记日志、置 `err=7`，并重新初始化相机管线。
- 硬件看门狗：如果固件提供 `machine.WDT`（EXP-00 确认），P5 中启用，超时时间设为 3s。

## 10. 性能规则

- 每个阶段（取帧、标记、检测、补偿、跟踪、打包、发送、遥测、gc）都要单独计时，在 1s 的窗口内统计 p50、p95、p99 和最大值，并通过遥测 S 行和 STATUS 上报。
- 主循环中不分配内存（缓冲区预先分配，打包时用 `struct.pack_into` 写入预先分配的 bytearray）。
- gc 策略由 EXP-05 决定：可以每 N 帧主动 `gc.collect()` 一次，也可以在空闲时做。单次 gc 耗时要计入统计。
