# 06 测试与验收规范

版本 v1.0（2026-11-19，Manager）。定义 PRD 中每个指标**怎么测、交什么证据、Manager 怎么复核**。

## 0. 通用规则

- **真值**：静态位置的真值来自"磁铁定位 + 人工读刻度"，记录到 0.5mm。要在报告里说明，人读刻度的误差约 ±0.5mm。
- **光照条件编号**（用于各项测试和数据集）：

| 编号 | 条件 |
|---|---|
| L1 | 只有室内顶灯 |
| L2 | 室内顶灯 + 我们的补光（**标准条件**） |
| L3 | 昏暗：关掉一半顶灯，有补光 |
| L4 | 强侧光：手机手电或台灯从侧面 45° 照射，或者靠窗的日光 |
| L5 | 频闪光源：普通 LED 台灯，用短曝光检查条纹；加上有人在旁边走动造成的阴影 |

- **原始数据**：每一帧都要保存 `seq、t_cap、status、u_px、pos_raw、pos_filt、vel、quality、各阶段耗时` 以及实验条件标签，格式为 CSV。
- **统计口径**：误差 = 测量值 − 真值。给出均值、标准差、RMS、最大绝对值、P95 绝对值。延迟和耗时给出 p50、p95、p99、最大值。
- **复现**：每个报告附一条命令，例如 `python tools/analysis/<脚本>.py reports/data/<编号>/`，必须能重新算出报告中的所有数字。

## 1. 测试项

### T1 静态精度与噪声（对应 M1、M2）

1. 摆杆水平，光照 L2。完成标定（25 个点，每 10mm 一个）。
2. **测试点和标定点错开**：取 −115、−95、−75、−55、−35、−15、+5、+25、+45、+65、+85、+105mm 这 12 个点，另外加上 0、±50mm。
3. 每个点用磁铁固定球，采集 300 帧（约 3–5s）。
4. 判定：
   - M1：所有点误差均值的最大绝对值 ≤ 2.0mm，RMS ≤ 1.0mm。
   - M2：每个点 pos_raw 的标准差都 ≤ 0.3mm。

### T2 检出与误检（对应 M6）

1. 在 L2 光照下，让球自由滚动或用手轻推往返，总共 ≥ 20,000 帧，球始终在杆上。
2. 再采集 3,000 帧以下特殊情况：手在画面上方晃过、球停在两端、球停在接缝或标记附近。
3. **误检判定**：用离线的高质量方法（高分辨率原图 + 人工抽查 200 帧，或者两种检测器交叉比对再人工复核分歧帧）产生参考值。凡是 `VALID=1` 但与参考值相差 >10mm 的帧，都算误检。
4. 判定：有效帧比例 ≥ 99.5%；误检比例 ≤ 0.05%，并且没有连续 2 帧的误检。

### T3 倾斜精度（对应 M3，同时用于 EXP-08）

1. 用垫块把摆杆固定在 θ ∈ {−6°, −3°, 0°, +3°, +6°}（如果机构允许，再加 ±10° 和 ±15°）。角度用手机测角仪读，误差 ±0.2°。
2. 每个角度下，用磁铁把球放在 x ∈ {−100, −50, 0, +50, +100}mm，每点采 200 帧。
3. 对比三种处理方式：不补偿、两标记补偿、三标记射影补偿。
4. 判定：采用三标记补偿时，|θ| ≤ 6° 范围内的最大误差 ≤ 3.0mm。

### T4 帧率与抖动（对应 M4）

1. 完整管线运行，并开启图传，有一个客户端在拉流。连续运行 10 分钟。
2. 统计 t_cap 的间隔分布，以及 seq 的跳号（丢帧）情况。
3. 判定：平均帧率 ≥ 60Hz；p99 帧间隔 ≤ 2 倍标称帧间隔。

### T5 端到端延迟（对应 M5，LED 法）

1. **需要人工**：把一个 LED 加 330Ω 限流电阻接到 K230 的一个空闲 GPIO 上（引脚由 Codex 指定，必须是 3.3V），把 LED 固定在画面内、ROI 之外的位置。
2. 程序用随机间隔（200–500ms）点亮或熄灭 LED，记录切换时刻 `t0`（`ticks_us`）。
3. 主循环检测 LED 区域的亮度跳变，记下第一个检测到跳变的帧发出 BALL 帧的时刻 `t1`。
4. 延迟 = t1 − t0（这包括了曝光时机的随机性，也就是"玻璃到串口"的全链路延迟）。采样 ≥ 500 次。
5. 同时，用一台 PC 通过 USB-TTL 读取 K230 的 UART，用另一个 GPIO 做同步，测出串口传输时间作为补充（可选）。
6. 判定：p95 ≤ 35ms。实测的 p50 和 p95 要写进 `config.latency_const_ms`，供 STATUS 上报。

### T6 动态跟踪（对应 M7）

1. 用垫块把摆杆固定在 θ ∈ {2°, 4°, 6°}。让球从上端的挡片处静止释放，滚到下端，每个角度做 5 次。
2. 对每次滚动，选出释放后、撞到挡片前的那一段，拟合 `x(t) = x0 + v0·t + ½·a·t²`。
3. 判定：拟合残差的 RMS ≤ 1.0mm；全程没有丢失；最大速度达到 ≥ 600mm/s 时仍然有效（如果角度不够大，就加长滚动距离，或者用手推）。
4. 顺便记录：拟合得到的加速度 a 与理论值 (5/7)·g·sinθ 的比值，供控制组建模参考。

### T7 图传（对应 M10）

1. **显示延迟**：在摄像头画面里放一部手机，运行毫秒级秒表；把笔记本屏幕放在旁边。用第三台设备拍照，同时拍下手机秒表和笔记本屏幕，两者的读数差就是延迟。采样 ≥ 20 次，取 p95。
2. **录像完整性**：连续做 10 次"开始 → 60s → 结束"，每次录像的时长和墙钟时间之差 ≤ 1s；用 `ffprobe` 检查文件没有损坏、没有大段时间空洞（时间戳间隔 > 0.5s）。
3. **断流恢复**：录像过程中关掉 AP 5s 再打开，检查是否自动续录，并且已经录下的文件完好无损。
4. **画质**：导出录像中的 5 帧原图（球分别在 −100、−50、0、+50、+100mm），人工确认 cm 刻度数字能看清，原图一并提交。
5. **对检测的影响**：同一场景下，分别在推流开启和关闭时测 T4 和 T5，帧率下降 ≤ 10%，延迟增加 ≤ 5ms。
6. **距离**：笔记本分别距离车 2m、4m、6m（模拟场外位置），并有人在中间走动，每个距离测 2 分钟，记录帧率和卡顿次数。

### T8 长时间稳定（对应 M8）

连续运行 60 分钟，完整管线 + 推流 + 遥测 + 串口（PC 模拟 MCU 发 RUN_INFO）。每分钟记录帧率、`gc.mem_free()`、温度（如果能读到）、错误计数。
**判定**：无崩溃；最后 5 分钟的帧率不低于前 5 分钟的 95%；空闲内存没有单调下降的趋势。

### T9 启动时间（对应 M9）

重复 10 次"断电 → 上电"，测量从上电到收到第一帧 `state=READY` 的 STATUS，以及到 RTSP 能拉到画面的时间。
**判定**：p95 ≤ 30s。

### T10 光照鲁棒性（对应 M11）

在 L1、L3、L4、L5 下重复 T1（只测 7 个点）和简化版 T2（每种光照 3,000 帧）。
**判定**：最大误差 ≤ 3mm，有效帧 ≥ 99%。

### T11 车载振动（对应 M12）

1. 把系统装到小车上，用磁铁在 x = 0 和 +50mm 处固定球（只为测试，比赛时不用）。
2. 小车按正常速度沿赛道跑一圈。
3. 统计行驶过程中测量值的标准差和偏差。**判定**：标准差 ≤ 1.0mm，偏差 ≤ 2.0mm。
4. 再让球自由放置，跑 3 圈，记录完整日志，统计有效帧比例和误检（方法同 T2）。

### T12 标定效率（对应 M13）

由**队员**按照 SOP 文档独立完成一次完整标定和一次快速复核，分别计时。
**判定**：完整标定 ≤ 5 分钟，快速复核 ≤ 1 分钟；结果满足 T1 的抽查（复测 3 个点）。

## 2. 实验（EXP）的报告要求

实验和测试不同：实验的目的是**回答问题、支持决策**。报告必须包括：

1. 要回答的问题，以及它关系到哪个决策（ADR 编号）。
2. 方法和变量（自变量、固定条件、样本量）。
3. 原始数据和分析脚本。
4. 结果，用表格加图表示。
5. **结论与建议**：建议采用哪个选项，理由是什么，置信度如何，还有哪些未覆盖的情况。
6. 如果结论和现有规范冲突，就提交变更请求（CR）。

## 3. Manager 的复核流程

每次验收，Manager 会：

1. 检出 Codex 的分支，运行 `pytest -q`。
2. 选 2 到 3 个指标，**用报告给出的命令重新计算**，并与报告中的数字核对。
3. 抽查原始数据是否合理，例如：时间戳是否单调、样本量是否够、有没有被挑选过的痕迹、条件标签是否齐全。
4. 审查代码是否符合 ICD 和算法规格，重点看协议、无效值处理和门控逻辑。
5. 在 `reports/review/<阶段>-review.md` 中给出结论：通过、有条件通过（附整改项），或者不通过。
6. 通过后合并到 `main`，并把看板状态改为 `DONE`。
