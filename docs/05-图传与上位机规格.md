# 05 图传与上位机（Station）规格

版本 v1.0（2026-11-19，Manager）。对应题目要求 1（6 分）。同时，评委很可能借助这路画面来判断钢球的位置误差，所以**画质和可靠性同样重要**。

## 1. 要求拆解

| 题目原文 | 工程要求 |
|---|---|
| 发送模块须稳固安装在小车上 | K230 本身就是发送端，刚性固定在车上 |
| 接收模块可连接显示存储装置，整体置于环形线路以外 | 场外放一台笔记本（或平板），通过 WiFi 接收 |
| 稳定实时显示钢球在凹槽中滚动的画面 | 显示延迟 ≤ 500ms（目标 ≤ 300ms），不卡顿；整根摆杆都要在画面里 |
| 完整记录每次测试时钢球运动的视频 | **每次测试一个文件**，从开始到结束不能缺段；断流后能自动续录 |
| 能按要求回放 | 有录像列表，能按测试号和时间找到文件，能播放、拖动进度 |
| 回传画面能完整清晰看到钢球的滚动轨迹并判定其位置 | 分辨率 ≥ 960×540；在画面里能读出 cm 刻度数字；建议叠加测得的位置数值 |
| 接收设备赛后与作品一起封存 | 准备一台**专用**的便宜设备，软件要能离线安装和运行 |

## 2. K230 端（发送）

### 2.1 主路径（ADR-09）

- 从 sensor 的 CHN1 取 YUV420SP 图像，送入**硬件 H.264 编码器**，再通过 RTSP 服务（`rtsp://<IP>:8554/hcv`）发出。
- **零拷贝优先**：优先把编码器直接绑定到 sensor 通道（MediaManager link）。如果必须由 Python 取码流，就用 `rtspserver_sendvideodata_byphyaddr()` 这类直接传物理地址的接口，**不要**在 Python 里逐包复制成 `bytes`【调研#10】。
- 默认参数：1280×720、30fps、2000kbps、GOP 15。最终取值由 EXP-12 确定。
- sensor 的帧率（例如 90fps）可能高于推流帧率。需要确认编码器能否按 `src_frame_rate/dst_frame_rate` 抽帧；如果不能，就在绑定链路上设置帧率控制（EXP-12）。
- 推流出现任何异常，都**不能影响测量主循环**：推流失败时置 `stream=3`，按退避策略重试，同时测量照常运行。

### 2.2 网络

- 默认使用 AP 模式（ICD §4.1）。AP 的 SSID、信道和密码都从配置文件读取。
- 赛场可能有很多 2.4G 设备，所以 EXP-12 要测信道 1、6、11 在干扰下的表现。必要时可以改焊 IPEX 外置天线（见硬件资料）。

### 2.3 可选：K230 端叠加（OSD）

- 默认**不做**（ADR-09），因为叠加由笔记本端完成。
- 如果 EXP-12 有余量，可以试验用硬件 OSD 层或 WBC 回写叠加一行文字（位置、目标、计时），条件是**不能破坏零拷贝路径**。
- 这样做的好处：即使笔记本端软件出问题，录下来的画面里也带着测量数值。

### 2.4 可选：TF 卡本地备份录像（F15）

- 用 `mp4muxer` 在 K230 本地录一份。只有 EXP-13 证明它对测量的影响 ≤ 3%，并且断电后文件仍然可用，才会启用。

## 3. Station（笔记本端软件，`station/`）

### 3.1 运行环境

- 必须支持 Windows 10/11（多数队员的笔记本是 Windows）；Linux 尽量也支持。
- Python 3.10 及以上，使用 PySide6（或 Tkinter）+ OpenCV + **ffmpeg**（ffmpeg 可执行文件随包附带）。
- 要能**完全离线**安装：提供离线安装包（wheel 文件和 ffmpeg），或者用 PyInstaller 打成单个可执行文件。

### 3.2 功能

| 编号 | 功能 | 要求 |
|---|---|---|
| S1 | 实时显示 | 低延迟拉流（参考参数：ffmpeg `-fflags nobuffer -flags low_delay -rtsp_transport tcp`，或者 VLC `--network-caching=200`）。显示窗口叠加遥测信息：钢球位置（mm）、目标位置、误差、测试号、计时、帧率、链路状态 |
| S2 | 分段录像 | 收到遥测 `RUN_STATE` 为 RUNNING 时自动开始录像，为 FINISHED/ABORTED 时再多录 2s 后停止。也可以手动点"开始/停止"。录像命令用 `ffmpeg -c copy`（不重新编码，CPU 占用低，画质无损）。文件名格式为 `YYYYMMDD_HHMMSS_T<测试号>.mp4` |
| S3 | 断流续录 | 断流后每秒重连一次；重连成功后写入一个新的分段文件（`..._part2.mp4`），**已经录下的部分绝不能丢失或损坏**（分段格式，或者每个分段都正确结束封装）。播放列表要把属于同一次测试的分段关联在一起 |
| S4 | 遥测记录 | 和视频同名的 `.csv` 文件，保存全部 T、S、E 行，每行附上笔记本的接收时间戳 |
| S5 | 回放 | 列出所有录像（按测试号和时间排列），可以播放、暂停、拖动、逐帧查看。回放时根据 CSV 叠加位置数值（通过 K230 时间戳和视频时间戳对齐，对齐方法写进报告） |
| S6 | 实时曲线 | 画出最近 10s 的位置和目标曲线，以及 ±10mm 误差带 |
| S7 | 测试小结 | 每次测试结束后，自动计算这次测试的最大误差、RMS、有效帧比例、用时，显示出来并保存（可以直接用在设计报告里） |
| S8 | 健康面板 | 显示 K230 状态、帧率、延迟、推流状态、标定 ID、最近一次快速复核的结果 |
| S9 | 快速复核向导 | 引导操作员完成 04 §5.4 的复核流程，并显示通过或不通过（需要 K230 端的配合程序） |

### 3.3 时间对齐

- 视频和遥测是两条独立的数据通道，叠加时需要对齐。
- 对齐方法要在报告中说明：可以用 K230 时间戳加上编码时间戳（PTS），也可以拍一个闪烁 LED 来标定两条通道之间的固定偏差（EXP-12 会测这个偏差）。
- 对齐误差目标 ≤ 50ms。

## 4. 备用图传方案（ADR-09 的推翻条件触发时）

| 方案 | 说明 | 由谁准备 |
|---|---|---|
| B1：降低参数 | 降低分辨率、帧率或码率，加大 GOP | Codex（EXP-12 中顺便测试） |
| B2：第二块 K230 或 ESP32-CAM | 用独立的摄像头和独立的板子专门做图传，和测量完全隔离 | 队员采购；Codex 做适配 |
| B3：5.8G 模拟图传 + USB 采集卡 | 延迟极低，完全独立；缺点是没有叠加信息，画质一般 | 队员询价，并评估摄像头是否能装下 |

**P4 开始前**，队员要先询价，并确认 B2 或 B3 能在 3 天内到货。
