# 车载平衡滚球系统：视觉测量设计与验证（草稿）

视觉系统给控制板提供沿槽方向的球心位置、速度及测量状态。相机固定在车身上方，K230 在车上完成图像处理并通过串口发给 MCU，场外电脑负责画面观察、录像与回放。控制板可以分别处理有效测量、短时预测、目标丢失和通信中断。[方案决策 ADR-01、ADR-02](02-方案设计与决策记录.md) · [接口规范](03-接口规范-ICD.md)

## 从一帧图像得到位置

在摆杆水平、相机与纸尺固定时，先采空槽图像和 **60 帧**列剖面作为背景。选取槽沿白尺条上长刻度尖端所在的窄带，避开短线和文字，识别刻度并人工核对印刷零点。被遮挡的刻度保留其空缺，其余锚点沿用原编号。将像素列与毫米位置做分段线性插值，保存背景、标定表和机位配置指纹。正式使用前，把钢球放在印刷零点复核；机位发生移动需要重新标定。[水平尺标定与现场步骤](../reports/M2-现场标定工具.md) · [标定程序](../tools/calib/ruler_lut.py)

每帧在槽内 **640 列 × 48 行**灰度区域计算列均值，同时保留二维像素。检测器消除整体亮度变化，按钢球与背景的明暗关系选候选，检查水平宽度和竖向轮廓；再将像素位置映射到毫米，交给 Kalman 跟踪器估计位置和速度。光照突变、目标丢失及重新进入时，控制板可以根据状态位决定是否采用数据。[板上检测路径与抗干扰修复](../reports/M2-板上抗干扰前置修复.md) · [板上主循环](../k230/main_hcv.py)

## 串口接口与损坏恢复

K230 以 **115200 bps、8N1** 发送二进制帧。每处理一帧发 **19 字节 BALL**，含序号、采集时间、状态、质量、原始及滤波位置、速度等；丢球时仍发包。**18 字节 STATUS** 通常以 **2 Hz** 报告状态和健康信息。接收端按同步头、长度和 CRC-8/SMBUS 校验；按照 `VALID`、`PREDICTED`、`CALIB_OK` 和 `FAULT` 决定能否采用位置。[ICD 的串口与报文字节表](03-接口规范-ICD.md) · [协议测试向量](../protocol/test_vectors.json)

电脑端逐字节核对了 **26 个**协议向量。固定种子的 **1,000,000 字节**噪声流中插入完整帧和坏帧，验证正确帧重新被找到；另对连续 **5,000 帧**注入翻转或截断，C 与 Python 解析结果逐帧一致，检查完好原帧保留、被破坏的原始记录未被原样接收。板上 UART 电平、物理回环和控制板实收待现场。[协议验证报告](../reports/P1-T03-协议库.md) · [噪声流用例](../tests/test_protocol.py) · [C/Python 抗损坏对照](../tests/test_c_protocol.py)

## 尺标精度与倾斜误差

水平尺软件验收使用带噪声、模糊、像素积分和遮挡的合成尺图。**24 个案例**覆盖线宽 **0.2/0.4 mm**、不同亚像素相位及最多 **3 条**被遮挡的长刻度。识别到 **22–25 条**正确编号的长刻度，逐条误差 **<0.3 px**；在 **−120 至 +120 mm** 逐毫米检查，插值误差 **<0.3 mm**。实物钢球在各位置的平均误差和抖动待现场。[合成验收报告](../reports/M2-现场标定工具.md) · [生成条件与独立真值断言](../tests/test_m2_ruler.py)

## 待现场验收

固定实际支架后，按同一机位完成零点、各静态点、灯光、空槽以及进出球记录。将视频中钢球首次出现或离开的帧与 BALL 状态变化对齐。具备线材和电平测量条件后补 UART 物理回环，与控制组就位后补上车闭环。图传仍需实拍验证颜色、持续显示、延迟、录像回放，以及开启图传对找球速度的影响。[到场清单](../tasks/下次到场清单.md)
