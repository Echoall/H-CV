# 备选方案：树莓派负责画面，K230 继续找球

**目前只留作备选，采购金额为零。** 如果湖北 K230 纯图传在板载 AP 和随身 Wi‑Fi 两种有效试验中都失败，再由负责人比较换固件和加树莓派。USB 自检中止或未取得录像时，两种网络的结论仍待验证。

## 两套设备分别做什么

湖北队在树莓派 5 上用 USB UVC 摄像头输出 MJPEG，uStreamer 通过局域网 HTTP 送到浏览器。网页可显示、测屏到屏延迟并在电脑本地录 WebM。上游配置默认 1280×720、期望 60 fps、端口 8080。湖北项目还有视觉识别和 UART 工程，本备选只取摄像头推流目录。来源为 `VincentttWang/NUEDC_2026` 固定提交 `ed079e501579cbe891e8339b6998f3ea53a12428` 下的 `2026H/vision_RPi5/raspberry-pi-camera-stream`，已核对 README、部署参数、服务及安装脚本。[上游版本](https://github.com/VincentttWang/NUEDC_2026/tree/ed079e501579cbe891e8339b6998f3ea53a12428/2026H/vision_RPi5/raspberry-pi-camera-stream)

| 路径 | 输入和输出 | 断开另一台设备时 |
|---|---|---|
| 测量与控制 | K230 原摄像头 → M1 检测与标定 → UART 的 BALL / STATUS → 控制板 | 应继续独立测量和发包 |
| 看画面与录像 | 第二只 USB 摄像头 → 树莓派 → 随身 Wi‑Fi → 电脑浏览器 | 应继续显示、录像和回放 |

两块板之间无需 USB、串口或视频线，也无需互传坐标。两台相机各有视场和时钟。现场若要在录像上逐帧叠加 K230 数据，还要做对时并核对两台相机的几何关系。湖北网页的 WebM 不直接满足 H-CV 现有按测试号存 MP4、对齐遥测和回放的全部要求，需另验。[项目图传规范](05-图传与上位机规格.md)

## 所需硬件、费用与安装

人民币金额为方案预算区间，按 2026-11-26 调研编列。公开样本中 PiShop US 的 Pi 5 2GB（SKU 9022-Pi5-2GB）显示 US$77.50。地区、运费和税费有差别，下表配件为工程预留，尚无国内成套报价。重量为载荷估算，到货后连同线材和紧固件实称。

| 项目 | 预算（元） | 车上新增质量估算 | 选择原因 |
|---|---:|---:|---|
| 树莓派 5，2 GB 档 | 500–750 | 45–55 g | 仅跑无桌面的推流服务，2 GB 为起测选择 |
| UVC 摄像头含短 USB 线 | 80–250 | 25–90 g | 须注明所需分辨率下能直接输出 MJPEG，核对实际帧率 |
| 32 GB microSD | 30–80 | 约 1 g | 系统、配置和日志，录像留在电脑 |
| 散热器或主动散热器 | 30–75 | 15–35 g | 持续推流时检查节流及安装间距 |
| 桌面调试 USB‑C 电源 | 80–150 | 留在桌上 | 官方推荐 27 W，优先借用合适电源 |
| 车载稳压与短供电线 | 70–160 | 20–70 g | 须与电池电压、Pi 5 输入和摄像头峰值耗流匹配 |
| 安装支架、隔离柱、紧固件 | 20–65 | 10–45 g | 固定第二只摄像头，避免线材牵拉 |

全套约 **810–1530 元**。只做台架验证可先扣除车载稳压一项，约 **740–1370 元**。上车载荷粗估 **116–296 g**，另加尚未选定的新增电池或随身路由；若复用现有无线网络，无需另买路由。现阶段只有 K230，表内物料都不能假定已有。

桌面先用独立的 Pi 5 电源，K230 保持原供电。官方资料说明，使用合适的 5 A 电源时下游 USB 外设有更高电流预算；用普通兼容电源时默认限制在 600 mA。上车前由电控组确认电池和稳压器能承受启动、无线发送及电机扰动时的负载，验证掉压、重启和摄像头重枚举。27 W 是电源规格，不能直接拿来算实际续航。树莓派和稳压器靠近底盘中心，摄像头单独架高到能看全摆杆的位置。避免遮挡 K230、压到活动部件或把重物加在摆杆上。[官方供电说明](https://github.com/raspberrypi/documentation/blob/master/documentation/asciidoc/computers/raspberry-pi/power-supplies.adoc)

## 借到设备后的最短验证流程

1. 给新卡写 Raspberry Pi OS Lite 64-bit，使树莓派和电脑连接同一个局域网。桌面先试有线网络也可。确认能在电脑访问树莓派；使用随身 Wi‑Fi 时检查客户端隔离。
2. 在树莓派安装 `v4l-utils`，接 USB 摄像头。用 `v4l2-ctl --list-devices` 查实际设备，再用 `v4l2-ctl -d /dev/video0 --list-formats-ext` 核实 MJPG、分辨率及帧间隔。若设备节点不同，同步修改上游服务的 `--device`。
3. 取上述固定提交的 `deploy` 目录。核对 `ustreamer.env` 与摄像头能力，先以 640×480、30 fps 验证。在树莓派该目录执行 `sudo bash install.sh`，再用 `systemctl status ustreamer` 核实服务。电脑浏览器用 `http://<树莓派局域网地址>:8080/` 看图，`/state` 查状态，`/stream` 是原始 MJPEG；换镜头后先用原始预览。
4. 镜头对准计时器并移动带纹理的物体。至少录 60 s，核对实际显示持续时间、帧率、延迟、拖动时的色块及录像回放。再到车上检查整根摆杆的可见性。湖北队 README 给出的约 60–100 ms 是对方系统报告，不能代入本项目。
5. 最后同时开 K230 原检测和树莓派画面，检查 K230 串口速率、时序、掉电重启和是否相互遮挡。分别停掉一个子系统，验证另一路仍能完成自己的任务。现场结果满足项目显示、录像、时序要求后再决策。

上游记录其摄像头在约 57 fps 时，720p MJPEG 约 61 Mbit/s，640×480 约 19 Mbit/s。随身 Wi‑Fi 的实际有效吞吐和摄像头的 JPEG 帧大小会改变结果，先低分辨率拿到实测，再决定是否上调；看见拥塞时也检查供电、摄像头格式和电脑解码。更换镜头后，上游的去畸变参数需要重新标定。[湖北参数与测量记录](https://github.com/VincentttWang/NUEDC_2026/blob/ed079e501579cbe891e8339b6998f3ea53a12428/2026H/vision_RPi5/raspberry-pi-camera-stream/deploy/ustreamer.env)

**预计工作量**（工程估算，设备到手后开始）：写卡部署和台架首画面 1–2 小时，两档网络与录像验证 1–2 小时，上车供电、固定和双系统复核约半天。若还需与现有 MP4 回放、测试编号、遥测时间轴整合，另留半天至一天。有车和电控配合后才能确认重量、重心、续航和移动中的实拍质量。
