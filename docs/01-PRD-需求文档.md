# 01 PRD：H 题视觉子系统需求文档

版本 v1.0（2026-11-19，Manager）。本文中的指标是**第一版目标**，后续可以通过实验结果和变更请求（CR）修订。

## 1. 背景

赛题《车载平衡滚球运动控制系统（H 题）》摘要：

- 小车沿黑线环形赛道顺时针行驶（直线段 AB、CD 各 1.5m，两端是半径 0.5m 的半圆），车上装有摆杆。
- 摆杆用 25cm 长的 4 分 PPR 水管（外径 2cm，壁厚 0.34cm）剖开制成凹槽，槽内放一颗直径约 1cm 的钢球。摆杆一端是合页，高度至少 5cm；另一端接角度控制机构。
- **凹槽内钢球的位置检测必须使用摄像头**（说明 7）。
- 摄像头可以装在凹槽上方，回传画面要覆盖整根摆杆，能清楚看到钢球怎么滚、在哪里（说明 6）。
- 凹槽边沿贴刻度（间距 0.1cm，不允许贴在槽内）。槽内壁要保持原状，不允许做任何增加摩擦的改造。

与 CV 直接相关的评分项：

| 要求 | 内容 | 分值 | CV 的作用 |
|---|---|---|---|
| 1 | 图传：发送端装在车上，接收端加显示存储设备放在场外；稳定实时显示，完整录下每次测试并能回放 | 6 | **CV 组全权负责** |
| 3 | 小车静止，球从 O 运动到 +5cm，折返到 −5cm 后稳定；≤5s，±5cm 处最大误差 ≤1cm | 13 | 提供位置反馈 |
| 4 | 行驶 A→B（≤8s），球稳定在中心附近，误差 ≤1cm | 20 | 提供位置反馈 |
| 5 | 行驶一圈（≤30s），球稳定在中心附近，误差 ≤1cm | 20 | 提供位置反馈 |
| 6 | 行驶一圈（≤30s），球稳定在任意指定位置附近，误差 ≤1cm | 20 | 提供位置反馈 |
| 7 | 其他 | 5 | 画面叠加信息、实时曲线等加分项 |
| 报告 | 测试方案、测试数据完整性 | 4+ | 提供测试数据和图表 |

**结论：100 分的作品分中，有 79 分直接依赖 CV 提供的位置数据和图传。**

## 2. 目标与非目标

### 目标

- G1：实时、准确、稳定地输出钢球沿摆杆的位置（mm）和速度，给控制组的 MCU 用。
- G2：图传满足要求 1：实时显示、按测试分段完整录像、可以回放。画面要能让评委看清钢球相对刻度的位置。
- G3：为设计报告提供可复现的测试数据和图表。
- G4：赛场上能快速复核和恢复，比如搬运之后 1 分钟内确认标定仍然有效。

### 非目标（明确不做）

- **不做循迹**：规则规定循迹只能用红外光电模块（说明 5），摄像头不能参与循迹。
- **不做摆杆控制**：PID 等控制算法在控制组的 MCU 上运行（理由见 ADR-02）。K230 只做测量。
- **不做计时显示**：规则要求显示屏不大于 2 英寸，由控制组负责。K230 不接屏幕来显示计时。

## 3. 用户与场景

| 场景 | 用户 | 需求 |
|---|---|---|
| 平时调试 | 控制组 | 稳定的位置数据；单位是物理量；有清楚的有效位和超时语义；有模拟器和解析代码 |
| 平时调试 | CV 组 | 能看画面、看曲线、录数据、离线复现 |
| 赛前 | CV 组 | 1 分钟复核标定；一眼确认系统正常（READY、帧率、推流状态） |
| 比赛测试 | 评委 | 场外屏幕实时看清钢球和刻度；每次测试都有完整录像，可以回放 |
| 写报告 | 全队 | 每次测试的位置曲线、误差统计和图表 |

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 每帧检测钢球，输出 pos_raw（标定后的 mm）、pos_filt（滤波后的位置）、vel（速度）、quality（质量）、status（状态） | Must |
| F2 | 通过 UART 按 ICD 协议发给 MCU，每帧发送一次 | Must |
| F3 | 标定：用钢球放在已知刻度的方法建立像素到 mm 的映射，覆盖 −120~+120mm | Must |
| F4 | 赛前快速复核：放 3 个点（0、±50mm），自动判定通过或不通过 | Must |
| F5 | 摆杆倾斜（透视）补偿 | Must（具体做法由 EXP-08 决定） |
| F6 | 丢球和异常时有明确的状态位，绝不输出"看起来合理"的假数据 | Must |
| F7 | 状态报文（STATUS）：系统状态、帧率、延迟、推流状态、错误码 | Must |
| F8 | 通过 WiFi 推送 H.264 视频，笔记本端实时显示 | Must |
| F9 | 笔记本端每次测试单独录一个文件，文件名带测试编号和时间；断流后能自动重连并继续录（不丢已经录下的部分） | Must |
| F10 | 笔记本端回放录像 | Must |
| F11 | 遥测：K230 通过 UDP 把位置数据发给笔记本，笔记本保存 CSV 并实时画曲线 | Should |
| F12 | 接收 MCU 发来的任务状态（测试编号、开始/结束、计时、目标位置），用于自动分段录像、在画面上叠加信息、写日志 | Should |
| F13 | 画面叠加信息：测得的位置、目标位置、计时，叠加在笔记本端或 K230 端 | Should（属于"其他"项加分） |
| F14 | 上电自启动、看门狗、出错后自动恢复；有安全启动开关 | Must（P5） |
| F15 | K230 本地 TF 卡备份录像 | Could（由 EXP-13 决定） |
| F16 | 用视觉估计摆杆倾角，提供给控制组参考 | Could |

## 5. 性能指标（v1 目标）

优先级：**可靠 > 准确 > 低延迟 > 高帧率**。

理由：小球的运动比较慢，控制带宽大约只有 1–3 rad/s。延迟从 20ms 变到 30ms，相位损失只有约 3°。但只要出现一次丢球或误检，就可能让控制器猛打舵，把球甩飞。

| 编号 | 指标 | 目标 | 测量方法 |
|---|---|---|---|
| M1 | 静态精度（摆杆水平，用非标定点测） | 最大误差 ≤ 2.0mm，RMS ≤ 1.0mm | 06 §T1 |
| M2 | 静态噪声（球静止 10s，pos_raw） | 标准差 ≤ 0.3mm | 06 §T1 |
| M3 | 倾斜精度（摆杆倾角 \|θ\|≤6°，球在 \|x\|≤100mm） | 最大误差 ≤ 3.0mm | 06 §T3 |
| M4 | 输出帧率（图传开着时） | ≥ 60Hz（目标 90Hz）；P99 帧间隔 ≤ 2 倍标称值 | 06 §T4 |
| M5 | 端到端延迟（曝光 → 串口发出） | P95 ≤ 35ms（目标 ≤ 25ms） | 06 §T5（LED 法） |
| M6 | 检出与误检（有补光、正常光照） | 球在杆上时有效帧 ≥ 99.5%；误差 >10mm 的"有效"帧 ≤ 0.05%，且不能连续出现 2 帧 | 06 §T2 |
| M7 | 动态跟踪 | 球速 ≤ 600mm/s 时不丢；匀加速段抛物线拟合残差 RMS ≤ 1.0mm | 06 §T6 |
| M8 | 长时间稳定 | 连续运行 60min 不崩溃，帧率衰减 ≤ 5%，内存不持续下降 | 06 §T8 |
| M9 | 启动时间（上电 → READY） | ≤ 30s（目标 ≤ 20s） | 06 §T9 |
| M10 | 图传 | 显示延迟 ≤ 500ms（目标 ≤ 300ms）；连续 10 次 60s 录像都没有缺段；画面上 cm 刻度数字清晰可读 | 06 §T7 |
| M11 | 光照鲁棒性（5 种光照） | M1 放宽到 3mm，M6 放宽到 ≥ 99% | 06 §T10 |
| M12 | 车载振动（行驶中，球用磁铁固定在已知位置） | 测量标准差 ≤ 1.0mm，偏差 ≤ 2.0mm | 06 §T11 |
| M13 | 标定效率 | 完整标定 ≤ 5min；赛前快速复核 ≤ 1min | 06 §T12 |

## 6. 规则合规清单（每个阶段验收时都要复查）

| 规则 | 我们的做法 |
|---|---|
| 钢球位置检测必须用摄像头 | ✅ 主要传感器就是摄像头 |
| 循迹只能用红外光电模块 | ✅ 摄像头不参与循迹，ROI 里不包含赛道 |
| 行驶中不得遥控或人为干预 | ✅ 所有计算都在车上完成。WiFi 只往外**发**数据；K230 不接受任何经 WiFi 下发、会影响测量或控制的命令（ICD §5） |
| 图传发送模块稳固安装在车上 | ✅ K230 和摄像头刚性固定在车上 |
| 接收模块和显示存储设备在场外，赛后一起封存 | ⚠ 接收设备会**被封存**，要准备一台专用的便宜笔记本或平板（见 07） |
| 槽内不能贴东西，不能增加摩擦 | ✅ 不贴任何额外标记，只用题目要求的槽外刻度尺做参考（ADR-03 决定）。标定时用的磁铁放在管子**外面**，用完就拿走 |
| 摆杆不能超出车身；车身 ≤ 35×25cm | ✅ 摄像头支架也要在这个范围之内（见 07） |
| 显示屏不大于 2 英寸 | ✅ K230 不接屏幕显示计时 |
| 车载电池供电 | ✅ K230 由车载电池供电（见 07） |

## 7. 里程碑

| 阶段 | 名称 | 出口条件（Gate） |
|---|---|---|
| P0 | 基线：板卡接入和摄像头能力摸底 | Codex 能可靠地操控板子；摄像头的模式、帧率、ISP 控制能力、视场角都有实测数据 |
| P1 | 数据与协议先行 | 有标注好的外观数据集；协议库和 MCU 模拟器交付控制组；确定补光方案和安装高度 |
| P2 | 检测、标定、倾斜补偿 | M1、M2、M3 在板上通过 |
| P3 | 实时链路 | M4–M7 通过；"CV v1"交付控制组联调 |
| P4 | 图传与上位机 | M10 通过，并且图传对检测的影响在允许范围内；如果不行，就切换到备用方案 |
| P5 | 上车集成与鲁棒性 | M8、M9、M11、M12、M13 通过；有比赛当天操作手册 |
