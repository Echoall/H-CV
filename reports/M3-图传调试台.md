## 电脑端验收

## 复现

```powershell
pytest -q
python -m station.bench.bench --simulate <ffmpeg.exe> <mediamtx.exe>
```

回环先选方案 1，再单独运行方案 2。每次输入 `1` 确认后等待摘要。`summary.json` 中 `capture` 列出帧数、解码帧率和尺寸，时长由帧数除以帧率。客户端 `vlc.stderr.log` 保留协商日志。配置和实际实验的使用方法见[图传调试台说明](../station/bench/README.md)。

在独立的 TCP 对照中，模拟视频发布就绪后第 8 秒终止发布进程。接收器约 17.76 秒后报告 EOF，此处计时从播放器进入播放开始。录像长度与播放器宣布 EOF 的时间分别记录，用于区分画面提前停止与播放器确认断开。

## 复核后补充

- 开跑前自检在方案菜单之前检查运行组件、VLC 和本地配置，读取板子媒体标志及 `info`。缺项或检测异常会停在自检，有中文提示和本机记录。只有通过后，才进入方案选择和用户确认；确认后按需同步板端模块。单元测试覆盖缺项不进入菜单、标志拦截和检查顺序。
- 方案 4 把大号毫秒时钟与 VLC 画面并排。从桌面启动 MediaMTX 模拟录得 1,049 帧、35.07 秒，并保存 7 张 2560×1600 整屏截图。核对截图左侧时钟和右侧播放区域均可见。截图留在本机，模拟摘要记录截图数量。真实延迟需让 K230 拍左侧时钟，在同一张图读两组数字。至少收 5 组，计算中位数和最大值，以最大值 ≤ 300 ms 判通过。测试覆盖 300 ms 和 301 ms 两侧以及样本不足。此次 VLC 日志显示嵌入窗口最终采用 Direct3D 11 输出。屏幕刷新和相机帧率会影响读数粒度。
- 桌面入口实板自检第一次无法打开 COM3，启动向导先停下并保存了日志。随后用 Windows 串口句柄和项目串口层确认端口重新可用，重跑自检通过媒体标志和 `info`，选 `0` 退出。未复位、切换网络或启动相机，端口第一次失败的根因未确定。
- 电脑模拟无窗口录制曾出现一次 Windows 客户端访问冲突 `0xC0000005`，输出 MP4 无法解码。无窗口模式去掉显示分支后，方案 1 无窗口和可见窗口各复跑通过，分别录到 891 帧、29.70 秒和 891 帧、29.68 秒。
- 用 `--simulate` 选方案 4 可复现录制和截图。模拟画面没有拍到电脑时钟，跑完保留「延迟待读」状态。板载 AP 实测和真实延迟尚未采集。
