# M3 / S5 电脑播放器延迟对照

2026-11-28，Windows 本机回环。实物摄像头和无线网络均未参与。

## 测量方法

电脑按 640×360、60 fps 生成带编号的灰度图。每张图中白块的行列编码帧号。主程序在把图写给 FFmpeg 前记下帧号和本机时刻。FFmpeg 9.0.2 编码 H.264，通过同一 MediaMTX 1.21.4 的本机 TCP 连接提供给各个播放器。两轮测试共享持续运行的发布端，先依次测试 VLC 100、150、200 ms 和 ffplay，再按相反顺序重复。每次连接约 18 秒，从首次输出起舍去前 2 秒，统计剩余不同帧号。

VLC 3.0.23 通过项目的显示加录像入口运行。YUV 输出管道读到完整图时记时。ffplay 9.1 启用 `-fflags nobuffer -flags low_delay`，读取 SDL 软件渲染器写出的 BMP，用文件最后写入时间记时。两端用同一电脑的时钟。每帧延迟包括图像输入、编码、本机传输、播放器处理和输出取样。两条输出路径及录像负载不同，跨播放器差值包含这些差异。逐帧输出时间可验证刷新间隔；网络包到达时间和物理屏幕发光时间仍待单独测量。

## 两轮结果

| 播放设置 | 首轮 / 次轮延迟中位数（ms） | 首轮 / 次轮 p95（ms） | 首轮 / 次轮缺失帧号 | 首轮 / 次轮最大输出间隔（ms） |
|---|---:|---:|---:|---:|
| VLC 100 ms | 453.73 / 453.75 | 455.71 / 455.82 | 0 / 0 | 21.05 / 20.90 |
| VLC 150 ms | 503.71 / 503.68 | 505.71 / 505.77 | 0 / 0 | 21.43 / 21.34 |
| VLC 200 ms | 553.72 / 553.69 | 555.85 / 555.54 | 0 / 0 | 21.21 / 21.22 |
| ffplay 低延迟 | 162.65 / 162.19 | 167.45 / 171.83 | 5 / 7 | 48.07 / 33.21 |

VLC 从 200 ms 调至 100 ms，两轮分别节省 99.99 和 99.94 ms。ffplay 两轮延迟更低，均有少量画面跳过。暂保留现有调试台默认设置。实板的 ≤300 ms 光学延迟，以及相同录像负载下哪种播放器更合适，仍待验证。

独立重开发布端，给 ffplay 低延迟模式再运行 70 秒。去掉启动和预热后，有效输出跨度为 67.351 秒，首尾之间共 4,039 个源帧号，观察到 4,018 帧，缺 21 帧（0.52%）。延迟中位数 177.88 ms，p95 为 186.34 ms。相邻输出最大间隔 37.78 ms，本轮满足连续 60 秒无超过 1 秒的输出空档。结果适用于本机合成画面与无窗口渲染路径。

## 复算与重跑

[阶段汇总](data/M3/bench/2026-11-28-player-summary.json) 和 [逐帧原始记录](data/M3/bench/2026-11-28-player-frames.json.gz) 使用相同的阶段名。原始记录每行依次为发布帧号、输入时刻和播放器输出时刻，时刻单位为纳秒。`missing` 是首尾编号之间未在渲染输出中观察到的编号数。以下命令在仓库根目录执行。

```python
import gzip
import json
import numpy as np

with gzip.open("reports/data/M3/bench/2026-11-28-player-frames.json.gz", "rt") as f:
    for stage, rows in json.load(f).items():
        ids, sent, seen = np.array(rows, dtype=np.int64).T
        age = (seen - sent) / 1e6
        print(stage, len(ids), np.percentile(age, [50, 95]), ids[-1] - ids[0] + 1 - len(ids),
              np.max(np.diff(seen)) / 1e6, (seen[-1] - seen[0]) / 1e9)
```

