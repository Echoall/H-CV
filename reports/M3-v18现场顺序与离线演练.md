| 电脑回放节拍 | 完整检测窗口内的帧数 | 检测与视频接收重叠 | 最大窗口处理 p95 | 时长法估计掉帧 |

| 60 fps | 4,140 | 68.996548 秒 | 854 µs | 0 |
| 90 fps | 6,240 | 69.330292 秒 | 823 µs | 0 |

收到一个 RTP 帧结束包时用主机时钟记时。选出没有超过 1 秒空档的最长连续接收区间。用检测开始、结束两条串口时钟锚点的偏移范围，把两端都落入该区间的完整检测窗口计入重叠。实板还要在驱动日志中确认实际选用的型号、分辨率和帧率。回放数据中该字段保留为空。

[演练状态、接收时刻和检测窗口原始记录](data/M3/bench/2026-11-28-visit-stages.json.gz) 可以用以下命令复算。

```python
import gzip
import json
from station.bench.hubei_m1 import during_interval

with gzip.open("reports/data/M3/bench/2026-11-28-visit-stages.json.gz", "rt", encoding="utf-8") as file:
    data = json.load(file)
for fps in (60, 90):
    row = data[f"s4-{fps}"]
    bounds = row["interval"]
    print(during_interval(row["detector_lines"], bounds["start_ns"]/1e9, bounds["end_ns"]/1e9, fps))
```

## 11 月 28 日修订后的正常退出观察

本轮使用 Windows 本机合成视频。播放器对照直接连接本机发布端，S4 使用同一个接收端及其计时中继，同时按 60/90 fps 回放既有检测条带。合成心跳使用实际经过的墙钟时间。实板插桩另用假编码器和发送器执行单元测试，上游 v1.8 摄像脚本仍通过原文件哈希检查。实板线程调度、插桩耗时、实际恢复用时及同场光学延迟均待操作者在场验证。

VLC 的起点取释放播放器后回报的主机时间。ffplay 路径由 FFmpeg 持有 RTSP 连接，从 FFmpeg 退出时计时，录后转封装和解码另行处理。S4 取这个时刻与中继上游套接字关闭时刻之中的较晚者。串口逐行加主机接收时间戳，结束界限取 `HCV_SERVICE_STOP_BEGIN`，同时要求脚本正常返回并保留随后出现的清理标记。

验收窗口取起点后的 15 秒。主线程每秒报告累计循环次数，编码线程报告累计取到帧数、发送调用返回次数、释放调用返回次数。每组相邻报告的所有计数须递增，窗口两端和相邻报告的空档均须 ≤1.75 秒（按一秒周期留 0.75 秒调度和串口余量）。计数反映本地调用进展。接收端视频另行解码并检查帧号。现场失联在当轮结束后保留证据，停止后续拍摄。

S1 演练核对了两种结果：v1.4 归档中缺完整处理窗口与采集起止时间，现场判据正确拒收；构造的边界样本验证 6,000 微秒的通过线以及超限和缺帧时的拒收。`s1_history_accepted=false` 和 `full_visit_accepted=false` 保留在总记录中。

from pathlib import Path
from types import SimpleNamespace

from station.bench.video_health import assess

root = Path(input("解压目录："))

    board = data["stages"]["board-session"]
    ok = assess(SimpleNamespace(directory=folder, summary=data), board["cleanup"] and board["exit_code"] == 0)
    health = data["post_client_health"]
    print(folder.name, ok, health["exit_to_stop_s"], health["threads"])
