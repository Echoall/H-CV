# M2 板上抗干扰前置修复

代码版本 `ca9d9dc`。Manager 在 Issue #5 要求，安排 M2 现场测试前恢复板上检测路径的半高宽、标定极性和二维形状检查。此前的一维快速路径在空槽局部干扰中误检 6/18，在有球局部干扰中检出 82/96，绝对误差 P95 为 266.52 px。旧路径的证据保存在 `reports/data/M1/equivalence/board-report.json`，可使用 `f0db70a` 的评测入口复算。

## 实现

板上主循环和合成复测均调用 `ProfileDetector.update(profile, predicted_u=…, roi_pixels=…)`。相机裁剪保留 48 行像素，列均值写入另一个预分配的 640 字节缓冲，NumPy 视图也在启动时创建并复用。拟合前先消除全局亮度变化，再按标定极性计算剖面残差。候选按滑动窗口响应排序，最多检查三个候选的水平半高宽及 48 行垂直轮廓。

板上动态数组和浮点临时值计入内存预算。首次加入二维检查时，注入有球和干扰的 60 帧分配探针测得单帧最多 5,152 B，原始日志见 `reports/data/M1/live-candidate-alloc.log`。随后复用列剖面视图，将阈值和质量计算移到定点路径，减少 Kalman 预测及更新中的临时对象。保留相同的运动模型和门控条件。

## 板上证据

固件 `v1.4-19-ga7de1c8`，MicroPython `1.21.0`，配置见 `reports/data/M1/m1-config.json`。相机模式 1280×720@90，检测通道 640×360，ROI 640×48。

| 测试 | 帧与检测结果 | 最大窗口处理 p95 | 单帧分配 |
|---|---|---:|---:|
| 固定无球，15 s 冒烟 | 1,352 帧，`VALID=0`，活动期丢帧 0 | 4,431 µs | — |
| 固定无球，35 s 回合 | 3,144 帧，`VALID=0`，活动期丢帧 0 | 4,402 µs | — |
| 固定无球，无 GC 分配探针 | 200 帧，没有候选 | — | 最大 1,984 B |
| 相机运行并注入有球加阴影的灰度 ROI，15 s | 1,351 帧，1,346 帧 `VALID=1`，活动期丢帧 0 | 5,247 µs | — |
| 注入同一灰度 ROI，无 GC 分配探针 | 60 帧，其中 56 帧检出，质量 103–255 | — | 最大 4,032 B，均值 3,832.53 B |

35 秒测试包含一个 `30.007754 s` 的完整无 GC 回合。回合间 GC 耗时 `81,647 µs`。按活动时长加 GC 复算，估计少处理 5 帧。分配测量使用 `gc.mem_free()` 的逐帧差值，覆盖真实相机取帧和检测、映射、跟踪、打包、UART 写入。注入测试使用合成 ROI 触发候选和跟踪，真实钢球仍需现场验证。

板上另以四组已知灰度图验证生产入口，每组 3 次。空槽、全高阴影和极性相反的目标均拒绝。有目标和阴影的 3 次均找到 `u=319.500 px`，裁剪及检测耗时 `5,069–5,096 µs`。测试后 USB `info` 成功。取回板上的三份主要源文件并逐一核对 SHA-256，与本轮代码一致。板上 JSON 配置与所附配置一致。
