# P1-EXP05 板上处理耗时基线

状态：Claude 有条件通过。实机复测等待 USB 恢复。

## 实验条件

- K230：幻尔 CanMV K230，COM3，固件 `v1.4-a7de1c8`。
- Sensor：1280×720@90，CHN0 640×360 灰度。
- ROI：`x=0, y=148, w=640, h=48`。
- 每项 1,000 次。
- UART：只使用 UART1，115200，物理 TX1 为 8 脚，未接外部设备。
- 原始日志：`reports/data/P1-EXP05/raw-timing.log`。
- 分析命令：

```text
python tools/analysis/p1_exp05.py reports/data/P1-EXP05/raw-timing.log \
  --output reports/data/P1-EXP05/metrics.json
```

## 结果

单位为微秒，分位数使用 NumPy 默认线性插值。

| 操作 | p50 | p95 | p99 | max |
|---|---:|---:|---:|---:|
| snapshot | 10774 | 11088 | 11558 | 12874 |
| copy ROI | 858 | 2544 | 2723 | 2769 |
| to_numpy_ref + mean | 410 | 540 | 2149 | 2331 |
| sum + box filter + argmax | 477 | 2091 | 2310 | 78961 |
| find_blobs 暗阈值 | 12173 | 13662 | 13796 | 15107 |
| find_blobs 亮阈值 | 10824 | 11081 | 11168 | 14604 |
| get_statistics | 1440 | 3066 | 3200 | 3267 |
| get_histogram | 1473 | 3166 | 3314 | 18636 |
| 3 个标记窗口剖面 | 57 | 75 | 164 | 1749 |
| 射影拟合 + 查表 | 64 | 92 | 184 | 46286 |
| struct.pack + UART1.write | 1645 | 3200 | 3331 | 3423 |
| gc.collect，无分配 | 1891 | 3617 | 3731 | 3808 |
| 分配 640 元素后 gc | 1924 | 3644 | 3770 | 4035 |
| 分配但不主动 gc | 2523 | 4243 | 4358 | 5012 |
| ticks_us | 2 | 2 | 3 | 1531 |

`gc.mem_free()` 从 3,824,224 字节开始，实验后为 2,447,072 字节。自动 GC 事件计数为 1 次。几何探针的电脑端和板端结果最大显示误差小于 0.0001 px，板端日志在 `reports/data/P1-EXP05/geometry-board.log`。

将实测分项的 p95 相加，得到列剖面方案的保守预算参考：

```text
to_numpy_ref + mean
+ sum + box filter + argmax
+ 3 个标记窗口剖面
+ 射影拟合 + 查表
+ struct.pack + UART1.write
= 0.540 + 2.091 + 0.075 + 0.092 + 3.200 ≈ 5.999 ms
```

这一参考值超过 4 ms。分项 p95 的和不等于流水线 p95。第 4 项还重复计算了列均值，跟踪滤波及最终检测逻辑尚未计入。完整流水线的纯处理时间仍需单独计时。

全宽 `find_blobs` 暗、亮阈值分别约 13.66 ms 和 11.08 ms，单独就接近或超过 90 fps 的帧周期。P2-EXP06 应分别验证列剖面及受限搜索窗口，ADR-04 的更新等待 Manager。

## UART1 写入和长跑补测

| 115200 / 460800 / 921600 独立测试 | p50 (µs) | p95 (µs) | p99 (µs) | max (µs) |
|---|---:|---:|---:|---:|
| 115200 | 1813 | 1814 | 1815 | 2066 |
| 460800 | 453 | 453 | 453 | 465 |
| 921600 | 248 | 248 | 248 | 250 |
| 115200，后台线程写入 | 1813 | 1814 | 1815 | 2075 |

每组 1,000 次。`uart-probe.log` 记录当前固件拒绝 `txbuf=256`。写入耗时随线路速率显著变化，支持当前调用阻塞的判断。`thread-probe.log` 只测了后台线程自身的写入耗时，主线程的切换抖动仍待测。基线保留 115200，可选提速见 [CR-P1-01](../docs/change-requests/CR-P1-01-UART1可选提速.md)。

关闭自动 GC 后，每 100 帧在单帧计时区间之外调用 `gc.collect()`。10,000 次循环的计时包含取帧、部分剖面计算、几何换算和 UART1 写入。p95 为 **11.485 ms**，最大 **13.570 ms**。循环索引由程序生成，原始数据只记录每轮执行时间，缺少连续取帧时戳和传感器帧序号。因此丢帧与手动 GC 停顿需要复测。复测将把 GC 纳入连续墙钟计时，并记录每帧的 `t_cap`，以相邻间隔超过 1.5 个帧周期标记疑似丢帧。该组未复现 78.961 ms 和 46.286 ms 的尖峰，现有证据不足以归因。原始数据在 `longrun.csv`，复算命令如下。

```text
python tools/analysis/p1_exp05.py reports/data/P1-EXP05/longrun.csv --longrun
```

相机开关对照只取得相机开启组，列均值 p50/p95/p99 为 396/508/2088 µs。关闭相机并释放媒体缓冲后读取旧数组引用的路径未能完成，USB raw REPL 恢复也失败。已改用独立 ROI 副本，待板子恢复后复测。原始记录在 `sensor-contention.log`。
