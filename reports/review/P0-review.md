## P0-T02 电脑端原型审查（`57c9c0d`）

### Codex 的问题 1：庐山派的 USB 端口能不能用 mpremote 的 raw REPL？

- **大概率可以，但还没实测。** 依据是，树莓派队在 CanMV K230（01Studio，CanMV v1.8）上就是用 USB raw REPL 上传、运行、`run --stream`，并把它当作恢复通道。庐山派用的也是 CanMV 这一系的固件。
- 需要注意两点：mpremote 支持 raw-paste 时会优先用它，不支持就自动退回普通 raw 模式；`fs_*` 系列函数依赖 `os.ilistdir` 和 `os.stat`。
- **接板后的验证顺序**：`ports` → `info` → `ls /sdcard` → `get`（读一个小文件）→ `put`（写到 /sdcard/hcv）。任何一步失败都立刻停下，把完整输出贴到 issue 里。
- **新的坑**：FAQ 里提到连上电脑后会出现"U 盘"，也就是 TF 卡通过 USB 大容量存储暴露给了电脑。**自动化脚本通过 REPL 写文件时，千万不要同时在电脑的 U 盘里改文件。** FAT 文件系统被两边同时写入，很可能损坏。请把这条写进 dev-setup，并提醒队员。

### Codex 的问题 2：超时后的回收要不要走 CanMV 专用路径？

需要。原因是：Ctrl-C 只在 Python 字节码层面检查中断。如果脚本卡在 C 层的阻塞调用里，比如 `sensor.snapshot`、网络操作或编码器，Ctrl-C 可能很久都不起作用；即使中断成功，媒体资源也没有释放。

建议按下面的顺序逐级回收：

1. 发送 Ctrl-C 两次，等待 3s，看能否回到 raw 提示符。
2. 不行就再发一次 Ctrl-C，然后用 Ctrl-B 退出 raw 模式、Ctrl-D 软复位，等待 10s，再重新进入 raw 模式。
3. 还不行，就用一个独立的退出码（例如 3）表示"需要人工断电重启"，并在 stderr 给出明确提示。

另外：

- 凡是用到媒体的板上脚本，一律写成 `try/finally` 释放资源，并在循环里调用 `os.exitpoint()`。
- 工具里加一个 `cleanup` 子命令（尝试执行 `MediaManager.deinit()`），每次超时之后先运行它。
- `verify.py` 里再加一个阻塞在 `time.sleep(100)` 里的超时用例。卡在媒体调用里的超时情况，放到 EXP-01 里实测，不计入 T02 的验收。

### Codex 的问题 3：首次备份的边界划在哪里合适？

只在第一次做、每次 `put` 之前都会检查——这个设计是对的。补充 4 点：

1. `run` 之前也要检查备份，因为脚本本身可能会写 TF 卡。
2. 除了 `main.py`，`/sdcard` 根目录下如果还有 `boot.py` 或其他 `*.py`，也一并备份，它们通常都很小。
3. **隐私**：仓库是公开的，而原来的 `main.py` 里可能写着 WiFi 密码之类的信息。原始备份文件请放到 `.gitignore` 忽略的本地目录里；仓库里只提交文件清单，以及每个文件的大小和 SHA-256。
4. 清单里写上总文件数和总大小，方便以后对照。

### 其他意见

- `project_path` 把写入范围限制在 `/sdcard/hcv` 之内，这个做法很好 ✅。P5 要改 `main.py` 时，再单独加一个需要显式开启的 `--allow-boot-file` 开关。

### B1（必须修）：首次备份会在实机上卡住

`backup_sdcard` 对 `/sdcard` 下的**每一个文件**都调用 `fs_hashfile(path, "sha256")`。我查了 mpremote 1.29.0 的源码：

- 如果板上没有 `hashlib.sha256`，它会走后备路径：通过串口**把整个文件读回电脑**，在电脑上计算哈希。
- 即使板上有 sha256，它也是在 MicroPython 里每次读 256 字节、循环计算。

CanMV 镜像的 TF 卡里自带大量例程，还有 kmodel 等大文件，总量可能有数百 MB。所以第一次备份可能要几十分钟，甚至几小时。而 `verify.py` 中每条命令的超时只有 90s，**第一步就会失败**。

修改要求：

1. 只对**根目录下的 `*.py`，以及大小 ≤ 1 MiB 的文件**计算 SHA-256；其余文件只记录路径和大小（如果能拿到修改时间，也一并记录），并在清单中标注 `"hashed": false`。
2. 先检查板上有没有 `hashlib.sha256`。没有的话，**不要回退到通过串口读取整个文件**：小文件才读回电脑计算，大文件直接跳过。
3. 首次备份作为单独的一步执行，超时设为 10 分钟，并在终端显示进度。`verify.py` 在开始前先确认清单已经存在。
4. 补充测试：用假设备模拟一个 50 MB 的文件，以及没有 hashlib 的情况，证明备份既不会把大文件读回电脑，也不会超时。

### W1（留意）：raw REPL 下软复位时 CanMV 会不会运行 main.py

上游 MicroPython 在 raw REPL 模式下软复位时，**不会**执行 `main.py`。但 CanMV 是分支版本，这一点还没有验证过。如果原有的 `main.py` 会启动摄像头，那么第二级回收（软复位）可能反而让板子卡住。

请在 EXP-00 的报告里记录：在 raw 模式下按 Ctrl-D 之后，板子的实际表现。

- P0-T02 的电脑端部分：**B1 修好后通过**。
