# M4 手动启动原型

电脑端原型，对应 [Issue #5 评论 7062471406](https://github.com/Echoall/H-CV/issues/5#issuecomment-7062471406) 里现在可以做的那一项。没有上板。

## 版本

- 分支 `codex/mvp`。提交哈希以 Issue #5 上同一次汇报为准。
- 固件未在本次运行。上次已知板上固件仍是 `v1.4-19-ga7de1c8`，本次没有新的 `info`。
- 没有新的 `config.json`。状态文件格式写在 `k230/hcv/boot.py`。

## 交付

- `reports/M4-自启动方案.md`：连续两次未完成的 `STARTING` 才进维护；一次上电最多提交一次；损坏记录按一次 `STARTING`。
- `k230/hcv/boot.py`：唯一的状态机、模拟看门狗和 `FAULT` 心跳。
- `k230/boot_manual.py`：USB 手动入口。不复制为 `/sdcard/main.py`，不导入相机或媒体模块。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_boot.py
.\.venv\Scripts\python.exe -m pytest -q
```

提交前在本机 `.venv` 跑过：`tests/test_boot.py` 为 12 passed，全套 `pytest -q` 为 265 passed。期望来自批准的计数规则。`STARTING` 计数 1 必须仍可再试；计数 2 必须进维护且看门狗保持关闭。

## 对照

| 项 | 结果 |
|---|---|
| 单次失败只计数，不进维护 | 电脑端 PASS |
| 连续第二次失败进维护，并组 `STATUS` `state=4` | 电脑端 PASS |
| 已在维护时不再写文件、不启用看门狗 | 电脑端 PASS |
| 成功进入测量后写 `RUNNING` 并把计数清零 | 电脑端 PASS |
| 模拟看门狗超时为 1.0 s，且只在完整帧后喂 | 电脑端 PASS |
| `SKIP_AUTOSTART` 和 Ctrl-C 不写文件、不导入相机 | 电脑端 PASS |
| 损坏正式文件按一次 `STARTING` | 电脑端 PASS |
| 半截临时文件不覆盖完好记录；完整临时文件在替换失败后仍生效 | 电脑端 PASS |
| 图传错误不第二次写启动记录 | 电脑端 PASS |
| 替换 `/sdcard/main.py` | 未执行，未批准 |
| 硬件看门狗触发或任何自动重启 | 未执行，未批准 |
| 板上手动运行、真实 UART、真实相机 | 未执行。上次 raw REPL 不能恢复，用户不在旁边 |

## 限制

原生层在状态文件提交前卡住时，这一次掉电不会增加计数。1.0 s 的超时覆盖已记录的约 82 ms GC、约 11 ms 帧间隔和 4.443 ms 处理 p95。初始化到首帧没有单独日志，方案里没有补一个未测的数。
