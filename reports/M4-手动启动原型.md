# M4 手动启动原型

电脑端原型，对应 [Issue #5 评论 7062471406](https://github.com/Echoall/H-CV/issues/5#issuecomment-7062471406) 里现在可以做的那一项。没有上板。

## 版本

- 分支 `codex/mvp`。提交哈希以 Issue #5 上同一次汇报为准。
- 固件未在本次运行。上次已知板上固件仍是 `v1.4-19-ga7de1c8`，本次没有新的 `info`。
- 没有新的 `config.json`。状态文件格式写在 `k230/hcv/boot.py`。

## 交付

- `reports/M4-自启动方案.md`：开机先写 `STARTING`，连续 90 个健康帧后再写 `RUNNING`，看门狗在第二次写入成功之后才启用。读到计数 2 的上电进入维护。一次上电最多写两次。
- `k230/hcv/boot.py`：唯一的状态机、模拟看门狗和 `FAULT` 心跳。
- `k230/boot_manual.py`：USB 手动入口。不复制为 `/sdcard/main.py`，不导入相机或媒体模块。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_boot.py
.\.venv\Scripts\python.exe -m pytest -q
```

提交前在本机 `.venv` 跑过：`tests/test_boot.py` 为 17 passed，全套 `pytest -q` 为 270 passed。期望来自 [评论 7063130683](https://github.com/Echoall/H-CV/issues/5#issuecomment-7063130683)。一次初始化卡死留下 `STARTING` 计数 1，下次仍启动；再卡死一次之后，下一次上电读到计数 2 才进维护。初始化耗时 3 s 时看门狗保持关闭。满 90 帧后才写 `RUNNING` 并启用看门狗。模拟看门狗到期时复位次数必须是 0。

## 限制

`STARTING` 写入之前就掉电，这一次不会增加计数。写入之后、90 帧之前卡住，计数留下。1.0 s 的超时只在看门狗启用之后生效，覆盖已记录的约 82 ms GC、约 11 ms 帧间隔和 4.443 ms 处理 p95。初始化到首帧没有单独的板上计时；电脑端用 3 s 的模拟初始化确认这段时间看门狗仍是关闭的。
